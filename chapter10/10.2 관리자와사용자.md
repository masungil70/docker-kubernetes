### 보안 관리를 위한 관리자의 업무
 
 관리자의 사용자 준비 3단계 체크리스트

  ✅ 1단계: 역할(Role) 생성 - "무엇을 할 수 있는지" 정의

   - 사용자에게 부여할 권한의 묶음인 Role 또는 ClusterRole을 YAML 파일로 작성합니다.
   - kubectl apply 명령어로 이 역할을 클러스터에 미리 등록합니다.

  ✅ 2단계: 사용자 인증서 생성 및 전달 - "누구인지" 증명

   - 사용자의 개인 키(.key)와 인증서 서명 요청(.csr)을 생성합니다.
   - 클러스터의 CA를 이용해 .csr에 서명하여 최종 사용자 인증서(.crt)를 만듭니다.
   - 생성된 개인 키(`.key`)와 서명된 인증서(`.crt`), 그리고 클러스터 CA 인증서(`ca.crt`)를 사용자에게 안전하게 전달합니다.

  ✅ 3단계: 역할 바인딩(RoleBinding) 생성 - "누가 무엇을 할 수 있는지" 연결

   - 1단계에서 만든 Role과 2단계에서 정의된 사용자(CN 값)를 연결하는 RoleBinding 또는 ClusterRoleBinding을 YAML 파일로 작성합니다.
   - kubectl apply 명령어로 이 바인딩을 클러스터에 미리 등록합니다

폴더 구조 
```
step3
├── admin-resource
│   ├── deployment-nginx.yaml
│   └── devlopment.yaml
├── admin-roll                           
│   ├── dev-user-binding.yaml    #rollbinding 설정 파일입니다 
│   └── pod-reader-role.yaml     #role 설정 파일입니다 

└── admin-user-csr-create
    ├── create_and_user_cert.sh    #사용자의 개인 키(.key)와 인증서 서명 요청(.csr)을 생성합니다.
    ├── csr.yaml
    └── dev-user-files.tar.gz      #생성된 개인 키(`.key`)와 서명된 인증서(`.crt`)를 사용자에게 안전하게 전달합니다.

```




위 작업을 쉽게 진행 할 수 있는 스크립트를 제공합니다.
```
vi create_and_user_cert.sh

#!/bin/bash

# 이 스크립트는 X.509 인증서를 사용하여 쿠버네티스 사용자 사용할 수 있는 키와 인증서, CA 인증서를 생성 압축파일로 묶는 과정을 자동화합니다.,
# 스크립트 실행 중 오류가 발생하면 즉시 중단됩니다.
set -e
# 스크립트가 실행되는 디렉토리 기준으로 파일을 찾도록 경로를 설정합니다.
cd "$(dirname "$0")"

# --- 변수 정의 ---
USER_NAME="dev-user"
USER_GROUP="development"
CSR_NAME="dev-user-csr"
KUBECONFIG_CONTEXT_NAME="dev-user-context"
# 현재 kubectl 컨텍스트의 클러스터 이름을 가져옵니다.
# 로컬 머신에 클러스터가 1개만 설정되어 있다는 가정 하에 동작합니다.
# 여러 클러스터가 있다면 이 부분을 수동으로 설정해야 할 수 있습니다.
CLUSTER_NAME=$(kubectl config view -o jsonpath='{.clusters[0].name}')
# 원래의 kubectl 컨텍스트를 저장해 둡니다.
ORIGINAL_CONTEXT=$(kubectl config current-context)

echo "--- [단계 1] 사용자 개인 키 생성 ---"
echo "${USER_NAME} 사용자의 2048비트 RSA 개인 키를 생성합니다. (dev-user.key)"
openssl genrsa -out ${USER_NAME}.key 2048
echo "개인 키 생성 완료."
echo

echo "--- [단계 2] 인증서 서명 요청(CSR) 생성 ---"
echo "개인 키를 사용하여 CSR을 생성합니다."
echo "CSR의 CN(Common Name)은 사용자 이름, O(Organization)는 그룹을 나타냅니다."
openssl req -new -key ${USER_NAME}.key -out ${USER_NAME}.csr -subj "/CN=${USER_NAME}"
echo "CSR 생성 완료. (dev-user.csr)"
echo

echo "--- [단계 3] 쿠버네티스 CertificateSigningRequest 오브젝트 생성 및 제출 ---"
# CSR 파일 내용을 base64로 인코딩합니다.
CSR_CONTENT=$(cat ${USER_NAME}.csr | base64 | tr -d '\n')
# 쿠버네티스에 CSR 오브젝트를 생성하기 위한 YAML 파일을 heredoc으로 만듭니다.
cat <<EOF | kubectl apply -f -
apiVersion: certificates.k8s.io/v1
kind: CertificateSigningRequest
metadata:
  name: ${CSR_NAME}
spec:
  request: ${CSR_CONTENT}
  signerName: kubernetes.io/kube-apiserver-client
  usages:
  - client auth
EOF
echo "쿠버네티스에 CSR 오브젝트 제출 완료."
echo

echo "--- [단계 4] CSR 승인 ---"
echo "관리자 권한으로 제출된 CSR(${CSR_NAME})을 승인합니다."
kubectl certificate approve ${CSR_NAME}
echo "CSR 승인 완료."
echo

echo "--- [단계 5] 서명된 인증서 추출 ---"
echo "승인된 CSR에서 서명된 인증서를 추출하여 ${USER_NAME}.crt 파일로 저장합니다."
# 인증서가 발급될 때까지 잠시 기다릴 수 있습니다.
sleep 2
kubectl get csr ${CSR_NAME} -o jsonpath='{.status.certificate}' | base64 --decode > ${USER_NAME}.crt
echo "인증서 추출 완료. (dev-user.crt)"
echo

echo "--- [단계 6] 생성된 파일들(key, crt, ca) 압축 파일로 생성합니다 ---"
tar -czf ${USER_NAME}-files.tar.gz ${USER_NAME}.key ${USER_NAME}.crt  -C /etc/kubernetes/pki/ca.crt
echo "압축 파일 생성 완료. (${USER_NAME}-files.tar.gz)" 

echo "5. 생성된 로컬 파일들(key, csr, crt) 삭제"
rm ${USER_NAME}.key ${USER_NAME}.csr ${USER_NAME}.crt
echo
echo "모든 정리 작업 완료."

```

### Kubernetes 사용을 위한 새 사용자 PC 설정 가이드

 예제시용 사용자 dev_user는 관리자로부터 전달받은 인증 정보를 사용하여, 자신의 새 리눅스 PC에서 쿠버네티스 클러스터에 접속하고 작업을 수행할 수 있도록 환경을 설정하는 방법입니다(Ubuntu/Debian 계열 리눅스 기준)

1단계: 저장소 업데이트 하기
```
sudo apt update
```

2단계: `kubectl` 설치하기
  kubectl은 쿠버네티스 클러스터와 통신하기 위한 공식 커맨드 라인 도구(CLI)입니다. 가장 먼저 이 도구를  설치해야 합니다.

1. 최신 버전의 `kubectl` 다운로드
```
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable-1.30.txt)/bin/linux/amd64/kubectl"
```

2. 다운로드한 바이너리 파일 실행 권한 부여
```
chmod +x ./kubectl
```

3. `kubectl`을 시스템 경로로 이동
어느 위치에서든 kubectl 명령어를 실행할 수 있도록, 시스템 PATH에 등록된 디렉터리로 파일을 옮깁니다.
```
sudo mv ./kubectl /usr/local/bin/kubectl
```

4. 설치 확인
버전 정보를 확인하여 kubectl이 성공적으로 설치되었는지 확인합니다.

```
kubectl version --client

#Client Version: v1.30.x (최신 안정 버전이 표시됩니다)
```

  3단계: 관리자로부터 인증 정보 수신 및 저장(dev-user-files.tar.gz)

  관리자에게 전달받은 압축 파일을 풀어야 합니다
```
tar -xzf dev-user-files.tar.gz
```  

  관리자에게 요청하여 다음 4가지 정보(파일 3개, 주소 1개)를 안전하게 전달받습니다.

   - dev-user.key (개인 키)
   - dev-user.crt (서명된 인증서)
   - ca.crt (클러스터 CA 인증서)
   - 클러스터 API 서버 주소 (예: https://master1.co.kr:6443)

   클러스터 API 서버 주소를 /etc/hosts 파일에 추가 합니다 
```
sudo vi /etc/hosts

192.168.80.165 master1.co.kr

```

  전달받은 인증서 파일들을 안전하고 찾기 쉬운 곳에 보관합니다. 홈 디렉터리 아래에 .kube라는 폴더를 만들고  그 안에 저장하는 것을 권장합니다.
```
# 홈 디렉터리 아래에 .kube 폴더 생성
mkdir -p ~/.kube

# 받은 파일들을 ~/.kube 폴더로 이동 (파일을 받은 경로에 따라 수정)
mv  dev-user.key  dev-user.crt ca.crt ~/.kube/
```
  3단계: 사용자 전용 `kubeconfig` 파일 생성

  이제 전달받은 인증 정보들을 사용하여 dev-user만을 위한 kubectl 설정 파일을 생성합니다. 이 파일은
  ~/.kube/config에 생성됩니다.

   1. 클러스터 정보 설정
```
# <cluster-name>은 식별하기 쉬운 이름, <api-server-url>은 관리자에게 받은 주소를 입력합니다.
 kubectl config set-cluster my-cluster \
  --server=https://master1.co.kr:6443 \
  --certificate-authority=/home/kosa/.kube/ca.crt \
  --embed-certs=true
```
   2. 사용자 인증 정보 설정
```
kubectl config set-credentials dev-user \
  --client-certificate=/home/kosa/.kube/dev-user.crt \
  --client-key=/home/kosa/.kube/dev-user.key \
  --embed-certs=true
```

   3. 컨텍스트(Context) 설정
      위에서 설정한 클러스터와 사용자를 연결합니다.
```
# <namespace>는 주로 작업할 네임스페이스(예: development)를 관리자에게 확인 후 입력합니다.
kubectl config set-context dev-user-context \
  --cluster=my-cluster \
  --user=dev-user \
  --namespace=development
```
   4. 기본 컨텍스트로 지정
```
kubectl config use-context dev-user-context
```

  5. 단계: `kubectl` 자동 완성 기능 활성화 (강력 추천)

  kubectl 사용 편의성을 크게 높여주는 자동 완성 기능을 쉘에 추가합니다.
```
# bash 쉘을 사용하는 경우
echo 'source <(kubectl completion bash)' >>~/.bashrc
source ~/.bashrc

```
  6단계: 연결 및 권한 테스트

  모든 설정이 완료되었습니다. 마지막으로 클러스터에 정상적으로 접속되는지, 그리고 부여받은 권한이 잘
  작동하는지 테스트합니다.

   1. 클러스터 접속 테스트
      클러스터 정보를 성공적으로 가져오는지 확인합니다.
```
kubectl cluster-info
```
   2. 권한 테스트
      관리자가 jane에게 부여한 역할(Role)에 따라 특정 명령어의 성공/실패 여부가 달라집니다.

       - 허용된 작업 시도 (예: 파드 조회 권한이 있는 경우)
```       
kubectl get pods
```
          > 정상적으로 파드 목록이 출력됩니다.

       - 거부된 작업 시도 (예: 노드 조회 권한이 없는 경우)
```
kubectl get nodes
kubectl get deploy
```
          > Error from server (Forbidden): nodes is forbidden... 메시지가 출력됩니다.

       - `auth can-i` 명령어로 직접 권한 확인
          자신이 특정 작업을 수행할 수 있는지 직접 물어볼 수 있습니다.
```
# development 네임스페이스에서 파드를 조회할 수 있는가?
kubectl auth can-i list pods --namespace development
```
          > yes (권한이 있는 경우)
          > no (권한이 없는 경우)

이제 dev-user의 리눅스 컴퓨터는 쿠버네티스 클러스터를 사용할 모든 준비를 마쳤습니다. dev-user은 관리자가 허용한 범위 내에서 안전하게 클러스터 리소스를 이용할 수 있습니다.
