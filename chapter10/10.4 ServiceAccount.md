 ServiceAccount란?

  ServiceAccount는 쿠버네티스 클러스터 내에서 파드(Pod) 안의 프로세스들이 사용하는 ID입니다.

   - `User` (사용자): 클러스터 외부의 사람을 위한 계정입니다. kubectl을 사용하는 개발자나 관리자가 여기에 해당합니다.
   - `ServiceAccount`: 클러스터 내부에서 실행되는 애플리케이션(프로세스)을 위한 계정입니다. 즉, 사람이 아닌 로봇을 위한 계정이라고 생각하면 쉽습니다.

  파드 안에서 실행되는 애플리케이션이 쿠버네티스 API 서버와 통신(예: 다른 파드 목록 조회, 디플로이먼트 생성 등)을 하려면, 자신이 누구인지 인증해야 합니다. 이때 사용하는 것이 바로 ServiceAccount입니다.

  ServiceAccount의 작동 원리

   1. 자동 할당: 파드를 생성할 때 특별히 지정하지 않으면, 해당 네임스페이스의 default라는 이름의 ServiceAccount가 자동으로 할당됩니다.

   2. 토큰(Token) 마운트: 파드에 ServiceAccount가 할당되면, 쿠버네티스는 해당 ServiceAccount를 위한 인증 토큰을 자동으로 생성하여 파드 내의 특정 경로(/var/run/secrets/kubernetes.io/serviceaccount/)에 파일 형태로 넣어줍니다(마운트).

   3. API 요청 시 사용: 파드 안의 애플리케이션은 이 토큰 파일을 읽어서, API 서버에 요청을 보낼 때 HTTP 헤더의 Authorization: Bearer <토큰 내용> 부분에 넣어 보냅니다.

   4. API 서버의 인증 및 인가: API 서버는 요청에 포함된 토큰을 보고 어떤 ServiceAccount가 보낸 요청인지 확인(인증)합니다. 그 후, 해당 ServiceAccount에 연결된 Role이나 ClusterRole을 확인하여 요청된 작업을 수행할 권한이 있는지 검사(인가)합니다.

  결론적으로, `ServiceAccount`는 파드가 API 서버에 자신을 인증하고, RBAC 시스템을 통해 권한을 부여받는 핵심적인 메커니즘입니다.

  ---

  예제: 네임스페이스의 파드 목록을 조회하는 파드 만들기

  자신이 속한 네임스페이스의 모든 파드 목록을 조회(list)할 수 있는 권한을 가진 파드를 만들어 보겠습니다.

  이를 위해서는 다음 4가지 쿠버네티스 오브젝트가 필요합니다.
   1. ServiceAccount: 파드가 사용할 ID
   2. Role: "파드를 조회할 수 있다"는 권한 정의
   3. RoleBinding: 위 Role과 ServiceAccount를 연결
   4. Pod: 위 ServiceAccount를 사용하여 실제로 권한을 테스트하는 파드

  아래 내용을 pod-lister.yaml 파일로 저장하고 사용하세요.
```
vi pod-lister.yaml

# 1. ServiceAccount: 'pod-lister-sa' 라는 이름의 서비스 어카운트 생성
apiVersion: v1
kind: ServiceAccount
metadata:
  name: pod-lister-sa
  namespace: default
---
# 2. Role: 'default' 네임스페이스에서 파드를 조회(get, list, watch)할 수 있는 역할 생성
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-lister-role
  namespace: default
rules:
- apiGroups: [""] # Core API 그룹
  resources: ["pods"]
  verbs: ["get", "list", "watch"]
---
# 3. RoleBinding: 위에서 만든 'pod-lister-role'을 'pod-lister-sa' 서비스 어카운트에 연결
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: pod-lister-binding
  namespace: default
subjects:
- kind: ServiceAccount
  name: pod-lister-sa # 권한을 부여받을 서비스 어카운트
roleRef:
  kind: Role
  name: pod-lister-role # 부여할 역할
  apiGroup: rbac.authorization.k8s.io
---
# 4. Pod: 위 서비스 어카운트를 사용하여 권한을 테스트하는 파드
apiVersion: v1
kind: Pod
metadata:
  name: pod-lister-test-pod
spec:
  # 이 파드가 'pod-lister-sa'의 ID와 권한을 사용하도록 지정
  serviceAccountName: pod-lister-sa
  containers:
  - name: kubectl-container
    image: bitnami/kubectl:latest
    # 파드가 시작되면 'kubectl get pods' 명령을 실행하여 권한을 테스트
    command:
      - "/bin/sh"
      - "-c"
      - |
        echo "--- 파드 목록 조회를 시도합니다... ---"
        kubectl get pods
        echo "--- 테스트 완료. 3600초 동안 대기합니다. ---"
        sleep 3600
```

  사용 및 권한 테스트 방법

   1. 위 YAML 파일 적용
```   
   kubectl apply -f pod-lister.yaml
```

   2. 테스트 파드의 로그 확인
      파드가 시작되면서 실행한 kubectl get pods 명령어의 결과를 로그를 통해 확인합니다.
```
kubectl logs pod-lister-test-pod
```

      예상 출력 결과:
```
--- 파드 목록 조회를 시도합니다... ---
NAME                    READY   STATUS    RESTARTS   AGE
pod-lister-test-pod     1/1     Running   0          15s
# (default 네임스페이스의 다른 파드들도 함께 출력됩니다)
--- 테스트 완료. 3600초 동안 대기합니다. ---
```
로그에 파드 목록이 성공적으로 출력되었다면, ServiceAccount와 RoleBinding이 올바르게 작동하여 파드가 권한을 획득했음을 의미합니다.
