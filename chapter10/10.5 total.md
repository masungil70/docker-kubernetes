 storage-admin ClusterRole의 권한을 사용하는 Pod, Deployment, Service를 만들어 보겠습니다.

  여기서 한 가지 중요한 개념이 있습니다.
   - 사용자(User): 클러스터 외부의 사람을 위한 계정입니다. (예: dev-user, dev-user2)
   - 서비스 어카운트(ServiceAccount): 클러스터 내부의 파드(Pod)가 API 서버와 통신할 때 사용하는 로봇 계정입니다.

  따라서 파드에게 storage-admin 권한을 주려면, ClusterRole을 User가 아닌 `ServiceAccount`에 연결(Binding)해야 합니다.

  아래 YAML 파일은 이 모든 과정을 한 번에 처리합니다.

   1. 파드가 사용할 storage-pod-sa 라는 ServiceAccount를 생성합니다.
   2. 기존 storage-admin ClusterRole을 storage-pod-sa ServiceAccount에 연결하는 ClusterRoleBinding을 생성합니다.
   3. storage-pod-sa ServiceAccount를 사용하는 Deployment를 생성합니다. 이 디플로이먼트의 파드 안에는 kubectl이 설치되어 있어, 권한을 바로 테스트해볼 수 있습니다.
   4. 네트워크 연결을 위한 Service를 생성합니다.

  ---

  storage-admin-resources.yaml

  아래 내용을 storage-admin-resources.yaml 파일로 저장하고 사용하세요.
```
vi storage-admin-resources.yaml

# 1. ServiceAccount: 파드가 사용할 로봇 계정
apiVersion: v1
kind: ServiceAccount
metadata:
  name: storage-pod-sa
  namespace: default
---
# 2. ClusterRoleBinding: storage-admin 역할을 위 ServiceAccount에 부여여
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: bind-storage-admin-to-sa
subjects:
- kind: ServiceAccount
  name: storage-pod-sa   # 1번에서 만든 ServiceAccount 이름
  namespace: default    # ServiceAccount가 있는 네임스페이스
roleRef:
  kind: ClusterRole
  name: storage-admin   # 이전에 만든 storage-admin ClusterRole
  apiGroup: rbac.authorization.k8s.io
---
# 3. Deployment: 위 ServiceAccount를 사용하는 파드를 생성
apiVersion: apps/v1
kind: Deployment
metadata:
  name: storage-admin-deployment
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: storage-admin
  template:
    metadata:
      labels:
        app: storage-admin
    spec:
      # 이 파드가 storage-pod-sa ServiceAccount의 권한을 사용하도록 지정합니다.지정합니다.
      serviceAccountName: storage-pod-sa
      containers:
      - name: kubectl-container
        image: bitnami/kubectl:latest # kubectl이 설치된 이미지 사용
        # 파드가 바로 종료되지 않도록 무한 대기 명령을 실행합니다.
        command: ["/bin/sh", "-c", "sleep infinity"]
---
# 4. Service: 디플로이먼트를 위한 네트워크 서비스 
apiVersion: v1
kind: Service
metadata:
  name: storage-admin-service
  namespace: default
spec:
  selector:
    app: storage-admin
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80 # 실제 파드에 열린 포트가 없으므로 의미는 없음
```

  사용 및 권한 테스트 방법

   1. 위 YAML 파일 적용
```
kubectl apply -f .
```
   2. 생성된 파드 이름 확인
```   
kubectl get pods
```

   3. 파드 내부로 접속
      kubectl exec 명령어를 사용하여, kubectl이 설치된 컨테이너 내부의 쉘로 들어갑니다.
```
# storage-admin-deployment-8644574d67-p86sz 부분에 위에서 확인한 파드 이름을 입력하세요.
kubectl exec -it storage-admin-deployment-8644574d67-p86sz -- bash
```
   4. 파드 안에서 권한 테스트
      이제 이 쉘은 storage-admin 권한을 가지고 있습니다. ClusterRole에 정의된 명령어들을 테스트해 봅니다.

       - 성공하는 명령어 (권한이 있는 작업)
```
# PersistentVolume 목록 조회
kubectl get persistentvolumes

# StorageClass 목록 조회
kubectl get storageclasses

# 모든 네임스페이스의 PersistentVolumeClaim 목록 조회
kubectl get persistentvolumeclaims --all-namespaces
```

       - 실패하는 명령어 (권한이 없는 작업)
          storage-admin 역할에는 pods를 조회할 권한이 없으므로 실패해야 정상입니다.
```
kubectl get pods
```
