Kubernetes(k8s)에서 사용하는 리소스 단위, 특히 메모리 단위인 Mi와 Gi에 대해 알아보겠습니다.

  컴퓨터 과학의 전통적인 2진법 표기법을 따르는 단위입니다.

   - Mi: 메비바이트(Mebibyte)를 의미합니다.
   - Gi: 기비바이트(Gibibyte)를 의미합니다.

  십진법 단위 (M, G) vs 이진법 단위 (Mi, Gi)

  우리가 일상적으로 사용하는 킬로(K), 메가(M), 기가(G)는 10의 거듭제곱(10^3, 10^6, 10^9)을
  기반으로 하는 십진법 단위입니다. 하지만 컴퓨터의 메모리나 저장 공간은 2의 거듭제곱으로 계산하는
  것이 더 정확합니다. Kubernetes는 이러한 혼동을 피하기 위해 명확한 이진법 단위를 사용합니다.

  주요 차이점:

   * 십진법 (SI 단위):
       * 1 MB (Megabyte) = 1,000 KB = 1,000,000 바이트
       * 1 GB (Gigabyte) = 1,000 MB = 1,000,000,000 바이트

   * 이진법 (IEC 단위 - Kubernetes가 사용):
       * 1 Mi (Mebibyte) = 1,024 KiB = 1,048,576 바이트 (2^20)
       * 1 Gi (Gibibyte) = 1,024 MiB = 1,073,741,824 바이트 (2^30)

  왜 Kubernetes는 이진법 단위를 사용할까요?
  컴퓨터 시스템에서 메모리는 2의 배수로 설계되고 측정되기 때문에, Mi, Gi와 같은 이진법 단위를
  사용하면 리소스를 더 정확하고 명확하게 할당하고 제한할 수 있습니다.

  Kubernetes YAML 파일 예시

  Pod의 리소스를 요청(requests)하거나 제한(limits)할 때 이 단위를 사용합니다.

```
apiVersion: v1
kind: Pod
metadata:
  name: resource-limit-pod-example
spec:
  containers:
  - name: my-container
    image: nginx
    resources:
      requests:
        memory: "64Mi"  # 컨테이너가 시작될 때 최소 64 메비바이트의 메모리를 요청합니다.
        cpu: "250m"     # CPU는 다른 단위를 사용합니다 (m = millicore).
      limits:
        memory: "128Mi" # 이 컨테이너는 최대 128 메비바이트의 메모리만 사용할 수 있도록 제한됩니다.
        cpu: "500m"

  요약


  ┌──────┬──────────┬─────────────┬───────────────┐
  │ 단위 │ 이름     │ 값 (바이트) │ 설명          │
  ├──────┼──────────┼─────────────┼───────────────┤
  │ Ki   │ Kibibyte │ 2^10        │ 1,024         │
  │ Mi   │ Mebibyte │ 2^20        │ 1,048,576     │
  │ Gi   │ Gibibyte │ 2^30        │ 1,073,741,824 │
  │ Ti   │ Tebibyte │ 2^40        │ ...           │
  └──────┴──────────┴─────────────┴───────────────┘


  중요: Kubernetes에서 메모리를 M이나 G로만 표기해도 Mi, Gi로 인식하기는 하지만, 명시적으로 Mi,
  Gi를 사용하는 것이 모호함을 없애는 가장 좋은 방법입니다.
