### 리소스 requests를 설정해야 하는 대표적인 상황 

"운영 환경(Production)에서 실행되는 모든 애플리케이션에는 `requests`를 설정하는 것이 원칙"입니다. 개발/테스트 환경이라도 설정하는 것이 좋습니다.

requests를 보장받아야 하는 주요 상황은 다음과 같습니다.

  1. 안정적인 서비스 성능을 보장해야 할 때 (가장 중요한 이유)

   - 상황: 사용자의 요청을 실시간으로 처리하는 API 서버나 웹 서버를 운영하고 있습니다.
   - `requests`가 없다면: 이 서버가 배포된 노드에 다른 "시끄러운 이웃(Noisy Neighbor)" Pod들이 CPU나 메모리를 갑자기 많이 사용하면, 내 API 서버가 필요한 자원을 할당받지 못해 응답이 느려지거나 타임아웃이 발생할 수 있습니다.
   - `requests`를 설정하면: requests: { cpu: "500m", memory: "1Gi" } 와 같이 설정하면, 다른 Pod들이 아무리 자원을 많이 써도 내 API 서버는 최소한 0.5 CPU와 1Gi 메모리를 항상 보장받습니다. 이로 인해 외부 요인에 관계없이 예측 가능하고 안정적인 성능을 유지할 수 있습니다.

  2. 애플리케이션이 정상적으로 시작되기 위해 최소 자원이 필요할 때

   - 상황: 애플리케이션이 시작(bootstrap)될 때 최소 2Gi의 메모리가 필요한 Java 애플리케이션이 있습니다.
   - `requests`가 없다면: Kubernetes 스케줄러는 이 사실을 모르고 남은 메모리가 1Gi 뿐인 노드에 Pod를 배치할 수 있습니다. Pod는 시작을 시도하다가 메모리 부족으로 즉시 종료(OOMKilled)되고, 계속 재시작하는 CrashLoopBackOff 상태에 빠지게 됩니다.
   - `requests`를 설정하면: requests: { memory: "2Gi" }로 설정하면, 스케줄러는 반드시 가용 메모리가 2Gi 이상인 노드에만 이 Pod를 배치합니다. 따라서 애플리케이션이 문제없이 시작되고 실행될 수 있습니다.

  3. 클러스터의 자원을 효율적으로 사용하고 싶을 때 (비용 최적화)

   - 상황: 여러 팀이 하나의 Kubernetes 클러스터를 공유해서 사용하고 있습니다.
   - `requests`가 없다면: 스케줄러는 각 Pod가 얼마나 많은 자원을 필요로 하는지 전혀 알 수 없습니다. 그래서 일부 노드에는 자원 소모가 큰 Pod들이 몰려 과부하가 걸리고, 다른 노드들은 텅텅 비어있는 자원 파편화가 발생합니다. 결국 불필요하게 더 많은 노드를 증설해야 해서 비용이 낭비됩니다.
   - `requests`를 설정하면: 스케줄러는 각 Pod의 요구사항을 정확히 알고, 마치 테트리스처럼 노드의 빈 공간에 Pod를 효율적으로 채워 넣습니다(이를 Bin Packing이라 합니다). 이를 통해 클러스터 전반의 리소스 사용률을 높이고 최소한의 노드로 최대한 많은 애플리케이션을 실행하여 비용을 절감할 수 있습니다.

  4. 자원 부족 시 내 서비스의 우선순위를 높이고 싶을 때

   - 상황: 한 노드에 갑자기 메모리가 부족해져서 Kubernetes가 일부 Pod를 강제로 종료(Evict)해야 하는
     상황이 발생했습니다.
   - `requests` 설정에 따라 Pod의 QoS(Quality of Service) 등급이 결정됩니다.
       - `BestEffort` (가장 먼저 종료됨): requests를 아예 설정하지 않은 Pod. 중요하지 않은 로그 수집기나 배치 작업 등에 사용됩니다.
       - `Burstable` (중간 순위): requests를 설정했지만 limits보다는 낮은 Pod. 일반적인 앱에 사용됩니다.
       - `Guaranteed` (가장 마지막에 종료됨): requests와 limits를 동일하게 설정한 Pod. DB나 API 서버 등 가장 중요한 애플리케이션에 사용됩니다.
   - `requests`를 설정하면: 내 Pod는 최소 Burstable 등급을 받게 되어, BestEffort 등급의 다른 Pod들보다 더 오래 살아남을 확률이 높아집니다. Guaranteed로 설정하면 최고 수준의 안정성을 보장받을 수 있습니다.
