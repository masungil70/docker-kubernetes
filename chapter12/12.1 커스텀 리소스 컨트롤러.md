 쿠버네티스에서 커스텀 리소스(Custom Resources)와 컨트롤러(Controllers)는 클러스터의 기능을 확장하고 자동화하는 데 핵심적인 역할을 하는 개념입니다. 이 둘은 떼려야 뗄 수 없는 관계이며, 함께 작동하여 오퍼레이터(Operator)라는 강력한 패턴을 형성합니다.

  1. 커스텀 리소스 (Custom Resources)

  정의: 커스텀 리소스는 쿠버네티스 API를 확장하여 사용자가 자신만의 새로운 오브젝트 타입을 정의할 수 있게 해주는 기능입니다. 쿠버네티스는 기본적으로 Pod, Deployment, Service와 같은 내장 리소스 타입을 가지고 있습니다. 커스텀 리소스를 사용하면 MyDatabase, MyApplication, CronJob (원래는 커스텀 리소스였음)과 같은 사용자 정의 리소스를 만들 수 있습니다.

  CustomResourceDefinition (CRD): 커스텀 리소스를 정의하기 위해서는 CustomResourceDefinition (CRD) 오브젝트를 생성하여 쿠버네티스 API 서버에 등록해야 합니다. CRD는 새로운 리소스의 이름, 버전, 스키마(어떤 필드를 가질 수 있는지) 등을 명세합니다.

  역할: 커스텀 리소스 자체는 데이터를 저장하는 역할만 합니다. CRD를 배포하고 커스텀 리소스 인스턴스를 생성하는 것은 마치 데이터베이스에 새로운 테이블 스키마를 정의하고 그 테이블에 데이터를 한 줄 추가하는 것과 같습니다. 이 데이터가 어떤 동작을 유발하지는 않습니다.

  예시: 새로운 리소스 타입 정의
```
vi greeting-crd.yaml
# Greeting CRD ()

# greeting-crd.yaml: 'Greeting'이라는 새로운 커스텀 리소스(Custom Resource)를 쿠버네티스에 정의합니다.
# 이 파일은 클러스터에 새로운 API 오브젝트 타입을 등록하는 역할을 합니다.
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  # CRD의 이름은 항상 '복수형.그룹명' 형식입니다.
  name: greetings.kosa.go.kr
spec:
  # 이 CRD가 속할 API 그룹입니다. (예: 'kosa.go.kr/v1' API)
  group: kosa.go.kr
  versions:
    - name: v1 # API 버전 (예: v1alpha1, v1beta1, v1)
      served: true # 이 버전의 API를 제공할 것인지 여부
      storage: true # 이 버전이 기본 저장 버전인지 여부 (여러 버전이 있을 경우)
      schema:
        openAPIV3Schema: # 리소스의 스키마 정의 (유효성 검사 및 자동 완성 지원)
          type: object
          properties:
            apiVersion:
              type: string
            kind:
              type: string
            metadata:
              type: object
            spec:
              type: object
              properties:
                message: # 'Greeting' 리소스의 spec에 포함될 'message' 필드
                  type: string
                  description: The greeting message.
                recipient: # 'Greeting' 리소스의 spec에 포함될 'recipient' 필드
                  type: string
                  description: The recipient of the greeting.
              required: ["message", "recipient"] # 'message'와 'recipient' 필드는 필수입니다.
  scope: Namespaced # 이 리소스는 특정 네임스페이스에 속합니다. (Cluster-scoped도 가능)
  names:
    plural: greetings # 복수형 이름 (kubectl get greetings)
    singular: greeting # 단수형 이름 (kubectl get geting)
    kind: Greeting # 리소스의 종류 (kind: Greeting)
    shortNames: ["greet"] # 짧은 이름 (kubectl get greet)

```

CRD 배포 (관리자 권한 필요) 
```
kubectl apply -f greeting-crd.yaml
```

커스텀 리소스 타입 목록을 확인 합니다 
```
kubectl get cdr 
```

새롭게 정의된 리소스 Greeting을 인스턴스화 하는 예제 
```
vi my-greeting.yaml
# my-greeting.yaml: 'Greeting' 커스텀 리소스의 실제 인스턴스(객체)를 정의합니다.
# 이 파일은 'Greeting' CRD에 정의된 스키마를 따르는 데이터 객체입니다.
apiVersion: kosa.go.kr/v1
kind: Greeting
metadata:
  name: hello-world # 이 'Greeting' 오브젝트의 고유한 이름
  namespace: default # 이 오브젝트가 생성될 네임스페이스
spec:
  message: "Hello" # 'Greeting' 리소스의 spec에 포함될 'message' 필드 값
  recipient: "World" # 'Greeting' 리소스의 spec에 포함될 'recipient' 필드 값

```   

커스텀 리소스 인스턴스 생성
```
 kubectl apply -f my-greeting.yaml
```

커스텀 리소스 인스턴스 생성된 된 것을 확인 합니다 
```
kubectl get greeting hello-world
# 또는
kubectl get greetings
# 또는 짧은 이름 사용
kubectl get greet
```

자세한 내용 확인:
```
kubectl get greeting hello-world -o yaml
```

2. 컨트롤러 (Controllers)

  정의: 컨트롤러는 쿠버네티스 자동화의 핵심입니다. 이는 클러스터의 "원하는 상태(Desired State)"를 "실제 상태(Actual State)"와 일치시키기 위해 지속적으로 작동하는 제어 루프(Control Loop)입니다.

  작동 원리:
   1. 감시(Watch): 컨트롤러는 특정 리소스(예: Deployment 오브젝트)의 변경 사항을 지속적으로 감시합니다.
   2. 비교(Compare): 감지된 변경 사항을 바탕으로, 리소스에 정의된 "원하는 상태"와 클러스터의 "실제 상태"를 비교합니다.
   3. 조정(Reconcile): 두 상태가 다르면, 컨트롤러는 실제 상태를 원하는 상태로 만들기 위한 일련의 작업을 수행합니다. (예: 파드 생성, 삭제, 업데이트)

  내장 컨트롤러 예시:
   - Deployment Controller: Deployment 오브젝트를 감시하고, ReplicaSet과 Pod를 생성/관리하여 원하는 수의 파드가 실행되도록 합니다.
   - Service Controller: Service 오브젝트를 감시하고, 클라우드 로드 밸런서나 네트워크 규칙을 생성하여 서비스에 접근할 수 있도록 합니다.

  3. 커스텀 리소스와 컨트롤러의 결합: 오퍼레이터(Operator) 패턴

  커스텀 리소스와 컨트롤러가 결합될 때 진정한 힘을 발휘합니다. 커스텀 컨트롤러는 특정 커스텀 리소스를 감시하도록 특별히 설계된 컨트롤러입니다. 이러한 커스텀 컨트롤러를 오퍼레이터(Operator)라고 부릅니다.

  작동 방식:
   1. 사용자가 Greeting 커스텀 리소스 인스턴스(hello-world)를 생성합니다.
   2. Greeting 커스텀 컨트롤러는 새로운 Greeting 리소스가 생성된 것을 감지합니다.
   3. 컨트롤러는 hello-world 리소스의 spec 필드(예: message: "Hello", recipient: "World")를 읽습니다.
   4. 컨트롤러는 이 정보를 바탕으로 실제 작업을 수행합니다. (예: "Hello World"라는 메시지를 로그에 출력하거나, 이메일을 보내거나, Slack 알림을 보냅니다.)
   5. 작업이 완료되면, 컨트롤러는 Greeting 리소스의 status 필드를 업데이트하여 현재 상태를 반영할 수 있습니다. (예: status.sent: true, status.lastSentTime: "...")

  4. 왜 중요한가?

  커스텀 리소스와 컨트롤러(오퍼레이터)는 쿠버네티스의 다음과 같은 강력한 기능을 가능하게 합니다.

   1. 확장성 (Extensibility): 쿠버네티스를 컨테이너 오케스트레이션 도구를 넘어, 모든 종류의 애플리케이션이나 인프라 컴포넌트를 관리할 수 있는 플랫폼으로 확장합니다.
   2. 운영 지식의 자동화 (Automation of Operational Knowledge): 데이터베이스(PostgreSQL, MariaDB 등), 메시지 큐, 캐시 등 복잡하고 상태를 가지는(Stateful) 애플리케이션의 배포, 스케일링, 백업, 복구, 업그레이드, 장애 복구 등 전문가의 운영 지식을 코드로 캡슐화하여 자동화합니다.
   3. 선언적 관리의 확대 (Expansion of Declarative Management): 쿠버네티스의 핵심인 "선언적 관리" 모델을 내장 리소스뿐만 아니라 사용자 정의 애플리케이션에도 적용할 수 있게 합니다. 사용자는 "무엇을" 원하는지만 선언하고, "어떻게" 구현되는지는 오퍼레이터가 알아서 처리합니다.
   4. 일등 시민(First-Class Citizens): 커스텀 리소스는 kubectl get, kubectl apply, RBAC(권한 관리) 등 쿠버네티스의 모든 기능과 통합되어 내장 리소스처럼 동작합니다.
   5. 플랫폼 구축 (Building Higher-Level Platforms): 플랫폼 팀이 조직 내 개발자들에게 복잡한 소프트웨어(예: "DB-as-a-Service", "CI/CD-as-a-Service")를 쿠버네티스 API를 통해 셀프서비스 형태로 제공할 수 있게 합니다.

커스텀 리소스와 컨트롤러는 쿠버네티스의 진정한 힘을 발휘하게 하는 핵심 메커니즘이며, 클라우드 네이티브 환경에서 복잡한 애플리케이션을 자동화하고 관리하는 데 필수적인 요소입니다.

- 이전에 실행된 모든 리소스를 삭제하고 진행 합니다:
```
  cd step1
  kubectl delete -f .
```

컨트롤러 예제
```
step2
├── greeting_controller
│   ├── backend                            #컨트롤러 백앤드 이미지 작성
│   │   ├── Dockerfile
│   │   ├── build.sh
│   │   ├── greeting_controller.py         #컨트롤러 기능 파이썬으로 기능 구현
│   │   └── requirements.txt
│   ├── greeting-controller-deployment.yaml   #그리팅 컨트롤러 디플로이먼트, 파드 선언 
│   └── greeting-controller.yaml              #커스텀 컨트롤러(오퍼레이터)가 쿠버네티스 API와 상호작용하기 위한 RBAC(Role-Based Access Control) 설정 파일
├── greeting-crd.yaml                         #커스텀 리소스 선언 파일
├── my-greeting-update.yaml                   #커스텀 속성 변경 하여 커스텀 컨트롤러 실행 확인
└── my-greeting.yaml                          #커스텀 리소스 인스턴스 파일
```

컨트롤러 Docker 이미지 빌드:
```
  cd step2/greeting_controller/backend
  chmod +x build
  ./build.sh
```

- 컴스텀 리소스를 배포 합니다 :
```
  cd ../..
  kubectl apply -f greeting-crd.yaml
  kubectl apply -f my-greeting.yaml
```

- 컨트롤러 Deployment 배포:
```
  cd greeting_controller
  kubectl apply -f greeting-controller.yaml
  kubectl apply -f greeting-controller-deployment.yaml
```
