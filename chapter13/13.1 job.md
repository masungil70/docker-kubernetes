1. Kubernetes Job이란?

  Kubernetes Job은 하나 이상의 파드(Pod)를 생성하고, 지정된 수의 파드가 성공적으로 완료될 때까지 실행을 보장하는 컨트롤러입니다.

  Deployment나 ReplicaSet처럼 계속 실행 상태를 유지하는 애플리케이션(예: 웹 서버)과 달리, Job은 시작과 끝이 있는
  명확한 작업(Task)을 처리하기 위해 사용됩니다. 작업이 성공적으로 완료되면 Job도 완료 상태가 됩니다.

2. Job은 언제 사용하나요?

Job은 다음과 같은 일회성 또는 배치(batch) 작업에 매우 유용합니다.

* 데이터 처리: 대량의 데이터를 가져와 처리하고 저장하는 ETL(Extract, Transform, Load) 작업
* 백업 및 복원: 데이터베이스나 스토리지의 데이터를 백업하는 스크립트 실행
* 메시지 큐 처리: 큐에 쌓인 메시지를 순차적으로 또는 병렬로 처리
* 배치 이메일 발송: 사용자들에게 대량의 이메일을 보내는 작업
* 과학 계산: 복잡한 계산이나 시뮬레이션을 수행하고 종료하는 프로그램

3. Job의 작동 방식

1. 사용자가 kubectl apply -f <job-file.yaml> 명령으로 Job을 생성합니다.
2. Kubernetes 컨트롤 플레인은 Job의 명세(spec)에 따라 파드를 생성합니다.
3. 파드 내의 컨테이너가 실행됩니다.
4. 성공: 컨테이너가 exit code 0으로 종료되면, Job은 해당 파드를 '성공적으로 완료'된 것으로 간주합니다.
5. 실패: 컨테이너가 0이 아닌 코드로 종료되거나(에러 발생), 파드가 노드 문제 등으로 삭제되면 Job은 이를 '실패'로 간주합니다.
6. 재시도: 실패 시, Job은 spec.backoffLimit에 지정된 횟수만큼 파드를 다시 생성하여 작업을 재시도합니다.
7. 완료: spec.completions에 지정된 수만큼 파드가 성공적으로 완료되면, Job은 '완료' 상태가 되며 더 이상 파드를 생성하지 않습니다.

중요: Job이 생성한 파드는 Job이 완료되더라도 자동으로 삭제되지 않습니다. 이는 작업 로그나 결과를 확인할 수 있도록 하기 위함입니다.

4. 주요 Job 설정 (spec 필드)

Job YAML 파일의 spec 섹션에서 동작을 제어할 수 있습니다.

* template: (필수) Job이 생성할 파드의 명세를 정의합니다. Deployment의 템플릿과 동일한 구조입니다.
    * spec.template.spec.restartPolicy: 파드 내 컨테이너의 재시작 정책입니다. Job의 경우 `OnFailure` 또는 `Never`만 사용할 수 있습니다. (Always는 허용되지 않습니다. Job의 파드는 언젠가 종료되어야 하기 때문입니다.)

* completions: Job이 성공적으로 완료해야 하는 파드의 총 개수입니다. 기본값은 1입니다.
    * 예: completions: 5 -> 5개의 파드가 성공적으로 실행을 마쳐야 Job이 완료됩니다.

* parallelism: 동시에 실행할 수 있는 파드의 최대 개수입니다. 기본값은 1입니다.
    * 예: completions: 10, parallelism: 2 -> 10개의 완료가 필요하지만, 한 번에 2개씩만 병렬로 실행됩니다. 파드 하나가 완료되면 다음 파드가 실행되는 식입니다.

* backoffLimit: Job이 실패로 간주되기 전까지 재시도할 횟수입니다. 기본값은 6입니다.

* activeDeadlineSeconds: Job이 활성화될 수 있는 최대 시간(초)입니다. 이 시간을 초과하면 Job은 실패로 처리되고 모든 실행 중인 파드가 종료됩니다.

5. 간단한 Job 예제

아래는 "Hello, Kubernetes Job!"을 출력하고 5초 후에 성공적으로 종료되는 간단한 Job 예제입니다.
```
vi my-job.yaml

apiVersion: batch/v1
kind: Job
metadata:
  name: hello-world-job
spec:
  template:
    spec:
      containers:
      - name: hello-world-container
         image: busybox:latest
         command: ["/bin/sh", "-c", "echo 'Hello, Kubernetes Job!' && sleep 5 && echo 'Job Done!'"]
      restartPolicy: OnFailure
```

이 파일을 my-job.yaml로 저장하고 다음 명령으로 실행할 수 있습니다.

```
# Job 생성
kubectl apply -f my-job.yaml

# Job 상태 확인
kubectl get jobs

# 생성된 파드 확인
kubectl get pods

# 특정 파드의 로그 확인 (작업 결과 확인)
kubectl logs <pod-name>
```

요약

* Job: 끝이 있는 작업을 위한 것.
* Deployment: 계속 실행되어야 하는 서비스를 위한 것.
* completions와 parallelism을 조합하여 순차, 병렬 등 다양한 실행 패턴을 만들 수 있습니다.
* backoffLimit으로 실패 시 재시도 횟수를 제어합니다.
