 1. Kubernetes CronJob이란?

Kubernetes CronJob은 리눅스 시스템의 cron 유틸리티와 매우 유사합니다. 지정된 시간 스케줄에 따라 `Job`을 주기적으로 생성하고 실행하는 컨트롤러입니다.

즉, 일회성 작업을 수행하는 Job을 원하는 시간마다 자동으로 실행시켜주는 자동화 도구라고 생각하시면 됩니다.

작동 흐름:
1. CronJob 컨트롤러는 현재 시간이 설정된 schedule과 일치하는지 계속 확인합니다.
2. 스케줄 시간이 되면, CronJob은 자신의 jobTemplate에 정의된 명세를 바탕으로 Job 리소스를 생성합니다.
3. 생성된 Job은 파드(Pod)를 생성하여 실제 작업을 수행합니다.
4. 작업이 완료되면 Job과 파드는 successfulJobsHistoryLimit와 failedJobsHistoryLimit 설정에 따라 기록으로 남거나 삭제됩니다.

2. CronJob은 어떤 상황에서 사용하나요?

CronJob은 정해진 시간에 반복적으로 실행되어야 하는 모든 종류의 작업에 적합합니다.

* 정기적인 백업: 매일 새벽 2시에 데이터베이스나 퍼시스턴트 볼륨(PV)의 데이터를 백업하는 작업.
* 주기적인 리포트 생성: 매주 월요일 아침 9시에 지난주 판매 실적 리포트를 생성하고 이메일로 발송하는 작업.
* 데이터 동기화: 외부 API와 데이터를 1시간마다 동기화하는 작업.
* 시스템 유지보수: 매일 밤 오래된 캐시 파일이나 임시 데이터를 삭제하는 작업.
* 인증서 갱신: 만료가 가까워진 SSL/TLS 인증서를 주기적으로 확인하고 갱신하는 작업.
* 뉴스레터 발송: 매월 1일 모든 사용자에게 월간 뉴스레터를 발송하는 작업.

간단히 말해, "~마다 한 번씩" 또는 "매일/매주/매월 ~시에" 실행되어야 하는 신뢰성 있는 자동화 작업이 필요할 때 CronJob을 사용합니다.

3. 주요 CronJob 설정 (spec 필드)

CronJob YAML 파일의 spec에서 핵심 동작을 정의합니다.

* schedule: (필수) Cron 표현식으로 작업을 실행할 스케줄을 정의합니다.
    * 형식: 분(0-59) 시(0-23) 일(1-31) 월(1-12) 요일(0-6, 0=일요일)
    * 예시:
        * */1 * * * *: 매 1분마다 실행
        * 0 17 * * 1-5: 평일(월~금) 오후 5시마다 실행
        * 0 4 1 * *: 매월 1일 새벽 4시에 실행
    * (참고: crontab.guru (https://crontab.guru/) 와 같은 사이트에서 표현식을 쉽게 만들고 테스트할 수 있습니다.)

* jobTemplate: (필수) 스케줄에 따라 생성될 Job의 템플릿입니다. 이 안에는 Job의 spec이 그대로 들어갑니다.

* concurrencyPolicy: 이전 Job이 아직 실행 중일 때 다음 스케줄 시간이 되었을 경우의 동작을 결정합니다.
    * Allow (기본값): 이전 Job과 상관없이 새 Job을 생성하여 동시에 실행될 수 있습니다.
    * Forbid: 이전 Job이 아직 실행 중이면 새 Job을 생성하지 않고 건너뜁니다.
    * Replace: 이전 Job이 아직 실행 중이면, 실행 중인 Job을 중단시키고 새 Job으로 교체합니다.

* startingDeadlineSeconds: 스케줄된 시간으로부터 여러 이유(클러스터 다운 등)로 Job 생성이 지연되었을 때, 마감 시간을
    설정합니다. 이 시간(초)을 넘기면 Job은 실행되지 않고 실패 처리됩니다.

* successfulJobsHistoryLimit / failedJobsHistoryLimit: 성공하거나 실패한 Job의 기록(Job 리소스와 파드)을 몇 개까지 보존할지 결정합니다. 기본값은 각각 3과 1입니다. 리소스 낭비를 막기 위해 적절히 설정하는 것이 좋습니다.

4. 간단한 CronJob 예제

아래는 매 1분마다 "Hello from CronJob"을 출력하는 간단한 예제입니다. (cronjob-example.yaml과 유사)
```
vi cronjob-history-limit-example.yaml

# CronJob의 successfulJobsHistoryLimit와 failedJobsHistoryLimit 예제
apiVersion: batch/v1
kind: CronJob
metadata:
  name: history-limit-example
spec:
  # 1분마다 실행하여 히스토리 제한을 쉽게 관찰할 수 있도록 스케줄을 설정합니다.
  schedule: "*/1 * * * *"

  # 보관할 성공한 Job의 최대 개수를 2개로 제한합니다.
  # 이 CronJob이 1분마다 실행되면서, 성공한 Job의 수가 2개를 초과하면
  # 가장 오래된 성공 Job부터 자동으로 삭제됩니다.
  successfulJobsHistoryLimit: 2

  # 보관할 실패한 Job의 최대 개수를 1개로 제한합니다.
  # 이 CronJob이 1분마다 실행되면서, 실패한 Job의 수가 1개를 초과하면
  # 가장 오래된 실패 Job부터 자동으로 삭제됩니다.
  failedJobsHistoryLimit: 1

  # 스케줄에 따라 생성될 Job 템플릿입니다.
  jobTemplate:
    spec:
      # Job이 실패했을 때 재시도 횟수를 0으로 설정합니다.
      # 이렇게 하면 실패한 Job 기록을 더 명확하게 볼 수 있습니다.
      backoffLimit: 0
      template:
        spec:
          containers:
          - name: success-or-fail-container
            image: busybox
            # 셸 스크립트를 사용하여 50% 확률로 성공 또는 실패를 반환하도록 설정합니다.
            # $RANDOM 값(0~32767)을 2로 나눈 나머지가 0이면 성공(exit 0), 아니면 실패(exit 1)합니다.
            command:
            - /bin/sh
            - -c
            - |
              echo "Running a job that might succeed or fail..."
              if [ $(($RANDOM % 2)) -eq 0 ]; then
                echo "Job Succeeded!"
                exit 0
              else
                echo "Job Failed!"
                exit 1
              fi
          restartPolicy: OnFailure


```

이 예제를 확인하는 방법

   1. CronJob을 클러스터에 배포합니다.
```
kubectl apply -f cronjob-history-limit-example.yaml
```

   2. 몇 분간 기다립니다. CronJob이 1분마다 실행되므로, 3~5분 정도 기다리면 여러 개의 Job과 파드가 생성되고 완료(또는 실패)됩니다.

   3. 생성된 Job과 파드의 목록을 주기적으로 확인합니다.
```
# watch 명령어를 사용하면 2초마다 결과를 갱신하여 보여줍니다.
watch kubectl get jobs,pods 

#또는 개별적으로 확인할 수 있습니다.
kubectl get jobs
kubectl get pods
```
예상 결과

  시간이 지나면서 kubectl get jobs 명령의 결과 목록에 history-limit-example-xxxxxxxx 형태의 Job이 나타날 것입니다.

   * 성공한 Job (`COMPLETIONS`가 `1/1`)은 최대 2개까지만 목록에 남아있게 됩니다. 3번째 성공 Job이 생기는 순간 가장 오래된 성공 Job이 사라집니다.
   * 실패한 Job (`COMPLETIONS`가 `0/1`이고 재시도가 없는)은 최대 1개까지만 목록에 남아있게 됩니다. 2번째 실패 Job이 생기는 순간 가장 오래된 실패 Job이 사라집니다.

  이렇게 successfulJobsHistoryLimit와 failedJobsHistoryLimit는 자동으로 완료된 Job 리소스와 관련 파드를 정리하여 클러스터가 지저분해지는 것을 방지하는 중요한 역할을 합니다.
