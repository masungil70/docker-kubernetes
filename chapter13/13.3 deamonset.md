1. Kubernetes DaemonSet이란?

쿠버네티스 DaemonSet(데몬셋)은 클러스터의 모든 노드(Node) 또는 특정 조건을 만족하는 모든 노드에 파드(Pod)의 복사본이 하나씩 실행되도록 보장하는 컨트롤러입니다.

Deployment가 가용한 노드에 파드를 분산하여 배포하는 것과 달리, DaemonSet은 '노드'를 기준으로, 각 노드마다 하나씩 파드를 배치하는 것이 핵심입니다. 클러스터에 새로운 노드가 추가되면 DaemonSet은 해당 노드에도 자동으로 파드를 배포하며, 노드가 제거되면 관련 파드도 정리(Garbage Collection)됩니다.

2. DaemonSet은 어떤 상황에 사용하나요?

DaemonSet은 클러스터의 모든 노드에서 실행되어야 하는 시스템 수준의 에이전트나 데몬을 배포할 때 매우 유용합니다. 각 노드의 상태를 모니터링하거나 로그를 수집하는 등의 역할에 이상적입니다.

* 로그 수집 에이전트: Fluentd, Logstash, Promtail 같은 로그 수집기를 각 노드에 배포하여, 해당 노드에서 실행 중인 모든 애플리케이션의 로그를 수집하고 중앙 로그 서버로 전송합니다. 가장 대표적인 사용 사례입니다.
* 노드 모니터링 에이전트: Prometheus Node Exporter, Datadog Agent, New Relic Agent 등을 각 노드에 배포하여 노드의 CPU, 메모리, 디스크, 네트워크 사용량과 같은 시스템 메트릭을 수집합니다.
* 클러스터 스토리지 데몬: GlusterFS, Ceph와 같은 분산 스토리지 시스템의 에이전트를 각 노드에서 실행하여 노드 로컬 스토리지를 클러스터 전체 스토리지 풀의 일부로 제공합니다.
* 네트워크 플러그인: 일부 CNI(Container Network Interface) 플러그인은 각 노드의 네트워크를 설정하고 관리하기 위해 DaemonSet으로 배포됩니다.
* 하드웨어 관리: 특정 노드에만 연결된 특별한 하드웨어(예: GPU)가 있을 경우, nodeSelector를 사용하여 해당 노드들에만 드라이버나 관리 에이전트를 배포할 때 사용합니다.

예재 : 

```
vi daemonset-example.yaml
apiVersion: apps/v1
kind: DaemonSet                           # [1]
metadata:
  name: daemonset-example
spec:
  selector:
    matchLabels:
      name: my-daemonset-example         # [2.1] 포드를 생성하기 위한 셀렉터 설정
  template:
    metadata:                              # [2.2] 포드 라벨 설정
      labels:
        name: my-daemonset-example
    spec:
      tolerations:                           # [3] 마스터 노드에도 포드를 생성
      - key: node-role.kubernetes.io/master
        effect: NoSchedule
      containers:
      - name: daemonset-example
        image: busybox                      # 테스트를 위해 busybox 이미지 사용
        args: ["tail", "-f", "/dev/null"]
        resources:                           # [4] 자원 할당량을 제한
          limits:
            cpu: 100m
            memory: 200Mi

```

설명 : 

[1] kind: DaemonSet을 명시하여 데몬셋을 사용한다고 선언.

[2.1] 데몬셋은 디플로이먼트처럼 라벨 셀렉터를 통해 파드를 생성.

[2.2] 라벨 셀렉터가 일치하는 파드를 YAML에서 정의해야 함.

[3] 데몬셋도 다른 쿠버네티스 오브젝트처럼 Pod 단위로 동작. 마스터 노드에는 기본적으로 Taint가 설정되어 있어 파드가 스케줄되지 않음. 마스터 노드에도 파드를 생성하려면 tolerations를 설정해야 하지만, 이는 필수는 아님.

[4] 데몬셋은 보통 노드 에이전트 역할(예: 로그 수집기, 모니터링 에이전트 등)을 하기 때문에,
자원 부족으로 데몬셋 파드가 중지되는 건 바람직하지 않음. 따라서 데몬셋은 리소스 QoS를 Guaranteed 클래스로 설정하는 것이 좋음. 이것 역시 필수는 아님.
