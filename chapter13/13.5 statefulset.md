### StatefulSet 이란?

StatefulSet은 상태를 가지는(Stateful) 애플리케이션을 관리하기 위한 Kubernetes 컨트롤러입니다. 데이터베이스(MySQL, PostgreSQL), 메시지 큐(Kafka, RabbitMQ), 분산 파일 시스템처럼 각 Pod가 고유한 상태(데이터, 식별자)를 유지해야 하는 경우에 사용됩니다.

일반적으로 사용하는 Deployment와 자주 비교되는데, 핵심적인 차이점은 다음과 같습니다.

* Deployment (Stateless): Pod들이 모두 동일하며, 언제든지 교체 가능한 "가축(Cattle)"과 같습니다. 아무 Pod나 죽이고 새로 만들어도 서비스에 영향이 없습니다. (예: 웹 서버)
* StatefulSet (Stateful): 각 Pod가 고유한 이름과 상태를 가지며, 대체 불가능한 "반려동물(Pets)"과 같습니다. db-0 Pod는 db-1 Pod와 다르며, 함부로 죽이거나 교체할 수 없습니다. (예: 데이터베이스 클러스터의 마스터 노드)

---

StatefulSet의 핵심 특징

StatefulSet은 상태 유지를 위해 다음 3가지 중요한 특징을 보장합니다.

1. 안정적이고 고유한 네트워크 식별자 (Stable, Unique Network Identity)

* Pod는 생성될 때 예측 가능한 고유한 이름을 갖습니다. 이름은 <StatefulSet 이름>-<순서(Ordinal Index)> 형식입니다. (예: mysql-0, mysql-1, mysql-2)
* 이 순서는 0부터 시작하며, Pod가 재시작되거나 다른 노드로 스케줄링되어도 절대 변하지 않습니다.
* 이 고유한 이름을 통해 다른 Pod들이 특정 Pod를 항상 같은 주소로 찾아 통신할 수 있습니다. (예: 데이터베이스 클러스터에서 마스터 노드를 찾을 때)

2. 안정적인 영구 스토리지 (Stable, Persistent Storage)

* StatefulSet은 각 Pod에 대해 고유한 PersistentVolumeClaim(PVC)을 생성하고 연결합니다.
* mysql-0 Pod는 data-mysql-0 PVC에 연결되고, mysql-1 Pod는 data-mysql-1 PVC에 연결되는 식입니다.
* 만약 mysql-0 Pod가 죽고 다시 생성되더라도, 새로운 mysql-0 Pod는 기존의 data-mysql-0 PVC에 다시 연결됩니다. 이를 통해 Pod가 사라져도 데이터는 안전하게 보존됩니다.

3. 순차적인 배포와 스케일링 (Ordered Deployment and Scaling)

* 생성/스케일업: Pod는 순서대로 하나씩 생성됩니다. mysql-0이 완전히 준비(Ready) 상태가 되어야 mysql-1이 생성되고, mysql-1이 준비되어야 mysql-2가 생성됩니다. 이는 클러스터형 애플리케이션에서 마스터 노드가 먼저 뜨고 복제본 노드들이 순서대로 참여하는 시나리오에 매우 중요합니다.
* 삭제/스케일다운: Pod는 생성의 역순으로 하나씩 삭제됩니다. replicas를 3에서 1로 줄이면, mysql-2가 먼저 종료되고, 그 다음 mysql-1이 종료됩니다. 이를 통해 데이터를 다른 노드로 안전하게 이전하거나 클러스터에서 정상적으로 탈퇴하는 등의 작업을 수행할 시간을 벌 수 있습니다.

---

Deployment vs. StatefulSet 비교


|특징|Deployment|StatefulSet|
|----|----|----|
| Pod 이름|랜덤한 해시값 (예: nginx-6799fc88d8-z5l7r)| 순서가 있는 고유한 이름 (예: web-0, web-1)|
|스토리지|여러 Pod가 공유하는 단일 볼륨 (ReadWriteMany)|각 Pod가 고유한 볼륨 (ReadWriteOnce)|
|스케일링/업데이트|한 번에 여러 Pod를 동시에 생성/삭제 (병렬)|순서대로 하나씩 생성/삭제(순차)|
|네트워크|Pod IP가 계속 변경됨 (Service를 통해 접근)|고유한 DNS 이름으로 항상 동일하게 접근 가능|
|주요 사용 사례|상태가 없는 웹 서버, API 서버 등|데이터베이스, 메시지 큐, 분산 시스템 등|

StatefulSet 예제 YAML

간단한 Nginx StatefulSet 예제입니다. 각 Nginx Pod가 고유한 index.html 파일을 갖도록 설정할 수 있습니다.

```
vi statefulset-svc.yaml

apiVersion: v1
kind: Service
metadata:
  name: statefulset-svc # StatefulSet이 Pod의 DNS 이름을 만들기 위해 사용하는 Headless Service
spec:
  clusterIP: None # Headless Service로 설정
  selector:
    app: pod-nginx
  ports:
    - name: web
      port: 80
```

```
vi statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: statefulset
spec:
  serviceName: statefulset-svc #  Headless Service 이름
  replicas: 3
  selector:
    matchLabels:
      app: pod-nginx
  template:
    metadata:
      labels:
        app: pod-nginx
    spec:
      containers:
      - name: nginx
        image: nginx
        ports:
        - containerPort: 80


```

YAML 설명:

* serviceName: statefulset-svc: StatefulSet이 각 Pod에 대해 고유한 DNS 주소(statefulset-0.statefulset-svc.default.svc.cluster.local 형식으로)를 생성하기 위해 사용하는 Headless Service를 지정합니다.

안정적인 영구 스토리지 (Stable, Persistent Storage) 예제 
StatefulSet을 사용하여 각 Pod에게 고유하고 독립적인 영구 저장 공간(Persistent Volume)을 어떻게 제공하는지 보여주기 위한 예제 입니다

nginx 웹 서버에 독립적인 영구 저장 공간을 설정하고 각 서버에 별도의 파일을 생성 한 후 각 Pod를 직접 curl로 호출하여 결과를 확인합니다 
운영 중인 파드를 종료 하고 다시 시작한 후 이전에 작성된 파일을 실행하여 각각의 pod에 영구적으로 저장공간에 생성된 파일이 존재하는 것을 확인 할 수 있습니다 

이 예제의 핵심은 두 가지입니다.

   1. 안정적인 Pod 신원 보장: StatefulSet은 Pod에게 statefulset-volume-0, statefulset-volume-1과 같이 예측 가능한 순서와 고유한 네트워크 이름(DNS 주소)을 부여합니다. 이는 Headless Service를 통해 이루어집니다.
   
   2. 안정적인 데이터 저장: 이 예제의 가장 중요한 부분으로, volumeClaimTemplates 섹션을 사용합니다.
       - StatefulSet은 이 템플릿을 바탕으로 각 Pod를 위한 별도의 `PersistentVolumeClaim`(PVC)을 자동으로 생성합니다.
       - 그 결과, statefulset-volume-0 Pod는 자신만의 저장 공간(PV)을 할당받고, tatefulset-volume-1 Pod도  자신만의 다른 저장 공간을 할당받습니다.
       - 만약 Pod가 재시작되거나 다른 노드로 옮겨가더라도, 항상 자신에게 할당되었던 바로 그 저장 공간에 다시 연결됩니다.

  결론적으로, 이 예제는 다음과 같은 상황을 시뮬레이션합니다.

  > 데이터베이스나 파일 서버처럼 각 인스턴스(Pod)가 자신만의 데이터를 저장하고 유지해야 하는 '상태가
  있는(Stateful)' 애플리케이션을 쿠버네티스에서 어떻게 안정적으로 운영할 수 있는가?

  StatefulSet과 volumeClaimTemplates를 함께 사용하면 Pod가 사라져도 데이터는 그대로 보존되기 때문에, 데이터의 영속성을 보장하며 상태 저장 애플리케이션을 운영할 수 있게 됩니다.

  사전 준비 : 
  volumeClaimTemplates이 사용하는 StorageClass 를 설치 해주세요 
```
kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.26/deploy/local-path-storage.yaml
```

```
mkdir step6 && cd step6
vi statefulset-volume.yaml

# StatefulSet 오브젝트 정의. 애플리케이션의 상태(데이터 등)를 유지해야 할 때 사용합니다.
apiVersion: apps/v1
kind: StatefulSet
metadata:
  # 이 StatefulSet의 이름입니다.
  name: statefulset-volume
spec:
  # Pod들의 고유한 네트워크 식별자(DNS 주소)를 생성하기 위해 연결할 Headless Service의 이름입니다.
  # 아래에 정의된 Service의 이름과 반드시 일치해야 합니다.
  serviceName: statefulset-volume-service
  
  # 이 StatefulSet이 관리할 Pod를 선택하기 위한 레이블 셀렉터입니다.
  # template.metadata.labels에 정의된 레이블과 일치해야 합니다.
  selector:
    matchLabels:
      name: statefulset-volume-example
      
  # 생성할 Pod의 개수(복제본 수)입니다. 각 Pod는 순서가 있는 고유한 이름을 갖게 됩니다 (예: statefulset-volume-0, -1, -2).
  replicas: 3
  
  # StatefulSet이 생성할 Pod의 명세(설계도)입니다.
  template:
    metadata:
      # Pod에 부착될 레이블입니다. 위 selector의 matchLabels와 일치해야 합니다.
      labels:
        name: statefulset-volume-example
    spec:
      containers:
      - name: statefulset-volume-example
        image: nginx
        ports:
        - containerPort: 80
          name: web
        # 컨테이너 내부에 마운트할 볼륨을 지정합니다.
        volumeMounts:
        # 마운트할 볼륨의 이름입니다. 아래 volumeClaimTemplates에 정의된 이름과 일치해야 합니다.
        - name: webserver-files
          # 컨테이너 내부에서 볼륨이 연결될 경로입니다.
          mountPath: /usr/share/nginx/html
          
  # PersistentVolumeClaim(PVC)을 동적으로 생성하기 위한 템플릿입니다.
  # StatefulSet은 이 템플릿을 사용해 각 Pod를 위한 고유한 PVC를 자동으로 생성합니다.
  # 결과적으로 각 Pod는 자신만의 독립적인 PersistentVolume(PV)을 갖게 되어 상태를 저장할 수 있습니다.
  volumeClaimTemplates:
  - metadata:
      # 생성될 PVC의 이름이자, 위 volumeMounts에서 참조하는 이름입니다.
      # 실제 생성 시에는 "webserver-files-<Pod이름>" 형식의 이름이 됩니다 (예: webserver-files-statefulset-volume-0).
      name: webserver-files
    spec:
      # 볼륨의 접근 모드를 설정합니다.
      # "ReadWriteOnce"는 단일 노드(Node)에서만 볼륨을 읽고 쓸 수 있도록 마운트하는 것을 의미합니다.
      accessModes: ["ReadWriteOnce"]
      
      # 사용할 스토리지의 종류를 정의하는 StorageClass의 이름입니다.
      # 클러스터에 미리 정의된 StorageClass 중 하나를 선택해야 합니다.
      storageClassName: local-path
      
      # 볼륨에 필요한 리소스 양을 설정합니다.
      resources:
        requests:
          # 요청할 스토리지의 크기입니다. 여기서는 100메가바이트(MiB)를 요청합니다.
          storage: 100Mi
---
# Headless Service 오브젝트 정의. Pod들에게 고유하고 안정적인 DNS 이름을 제공하는 역할을 합니다.
apiVersion: v1
kind: Service
metadata:
  # 이 Service의 이름입니다. 위의 StatefulSet의 serviceName과 일치해야 합니다.
  name: statefulset-volume-service
spec:
  ports:
    - port: 80
      name: web
      
  # clusterIP를 "None"으로 설정하여 이 Service를 Headless Service로 만듭니다.
  # Headless Service는 자체의 IP 주소를 갖지 않고, 대신 selector로 선택된 Pod들의 IP 주소를 직접 DNS에 등록합니다.
  clusterIP: None
  
  # 이 Service가 연결될 Pod를 선택하기 위한 레이블 셀렉터입니다.
  # StatefulSet의 template.metadata.labels에 정의된 레이블과 일치해야 합니다.
  selector:
    name: statefulset-volume-example
```
