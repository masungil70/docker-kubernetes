### cAdvisor 모니터링을 위한 Nginx + FastAPI 테스트 환경 구축 (Docker Compose 사용)

  1. 프로젝트 폴더 구조
```
cadvisor/
├── Dockerfile
├── docker-compose.yml
├── main.py
├── nginx.conf
├── requirements.txt
└── run_test.sh
```

  2. FastAPI 애플리케이션 (main.py)
  간단한 API 두 개를 가진 FastAPI 앱입니다. 하나는 기본 메시지를 반환하고, 다른 하나는 의도적으로
  CPU를 약간 사용하여 부하를 발생시킵니다.
```
vi main.py


from fastapi import FastAPI
import math

app = FastAPI()

@app.get("/")
def read_root():
    """기본 환영 메시지를 반환합니다."""
    return {"message": "Hello, FastAPI with Nginx and cAdvisor!"}

@app.get("/calculate")
def calculate(iterations: int = 20000, inner_iterations: int = 1000):
    """
    의도적으로 CPU 부하를 80% 이상으로 높이기 위해 복잡한 연산을 수행합니다.
    (iterations * inner_iterations) 만큼의 연산이 수행됩니다.
    """
    result = 0
    # 0으로 나누거나 로그를 취하는 것을 피하기 위해 1부터 시작합니다.
    for i in range(1, iterations + 1):
        for j in range(1, inner_iterations + 1):
            # 좀 더 복잡하고 무거운 연산 수행
            result += math.log(i) * math.sin(j) - math.sqrt(j) * math.cos(i)
    
    return {"message": f"Heavy calculation finished after {iterations}x{inner_iterations} iterations."}


```
✦ 3. Python 의존성 파일 (requirements.txt)
  FastAPI 앱 실행에 필요한 라이브러리 목록입니다.
```
vi requirements.txt

fastapi
uvicorn
```

✦ 4. FastAPI 앱을 위한 Dockerfile (Dockerfile)
  Python 코드를 컨테이너 이미지로 만들어주는 설정 파일입니다.

```
vi Dockerfile

# Python 3.9 버전을 기반으로 이미지를 생성합니다.
FROM python:3.9-slim

# 작업 디렉토리를 /app으로 설정합니다.
WORKDIR /app

# requirements.txt를 먼저 복사하고 라이브러리를 설치합니다.
# (코드 변경 시 라이브러리를 다시 설치하지 않도록 하여 빌드 속도를 높입니다.)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 현재 디렉토리의 모든 파일을 /app 디렉토리로 복사합니다.
COPY . .

# 8000번 포트를 외부에 노출합니다.
EXPOSE 8000

# 컨테이너가 시작될 때 uvicorn 서버를 실행합니다.
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

```

✦ 5. Nginx 설정 파일 (nginx.conf)
  Nginx가 받은 요청을 FastAPI 컨테이너로 전달(리버스 프록시)하도록 설정합니다.
```
vi nginx.conf

events {};

http {
    server {
        listen 80;

        location / {
            # "api"는 docker-compose.yml 파일에 정의된 FastAPI 서비스의 이름입니다.
            proxy_pass http://api:8000;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
}

```


✦ 6. Docker Compose 설정 파일 (docker-compose.yml)
  api, nginx, cadvisor 3개의 서비스를 정의하고 한 번에 실행하도록 설정합니다.

```
vi docker-compose.yml

version: '3.8'

services:
  # 1. FastAPI 애플리케이션 서비스
  api:
    build: .
    container_name: fastapi_app
    restart: always

  # 2. Nginx 리버스 프록시 서비스
  nginx:
    image: nginx:latest
    container_name: nginx_proxy
    ports:
      - "8080:80" # 호스트의 8080 포트를 컨테이너의 80 포트로 연결
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro # nginx.conf 파일을 컨테이너에 마운트 (읽기 전용)
    depends_on:
      - api # api 서비스가 실행된 후에 nginx 서비스가 실행되도록 설정
    restart: always

  # 3. cAdvisor 모니터링 서비스
  cadvisor:
    image: gcr.io/cadvisor/cadvisor:latest
    container_name: cadvisor
    privileged: true
    ports:
      - "8081:8080" # 호스트의 8081 포트를 컨테이너의 8080 포트로 연결
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:rw
      - /sys:/sys:ro
      - /var/lib/docker/:/var/lib/docker:ro
    devices:
      - /dev/kmsg
    restart: always

```

✦ 실행 방법

     터미널에서 해당 폴더로 이동한 후, 아래 명령어를 실행하세요.
```
   docker compose up -d
```
  이 명령어는 docker-compose.yml 파일을 읽어 3개의 컨테이너를 백그라운드에서 실행하고 빌드합니다.

  성능 분석 및 확인

  모든 컨테이너가 정상적으로 실행되었다면, 이제 각 서비스에 접속하여 성능을 분석할 수 있습니다.

   1. FastAPI 서비스 접속
       * 웹 브라우저나 curl을 사용하여 http://hostserver:8080 에 접속합니다. Nginx를 통해 FastAPI의 환영 메시지가 보일 것입니다.
       * http://hostserver:8080/calculate 에 접속하면 CPU 부하를 발생시키는 API를 호출할 수 있습니다.

   2. cAdvisor 대시보드 접속
       * 웹 브라우저에서 http://hostserver:8081 로 접속하세요.
       * cAdvisor UI가 나타나면, 상단의 "Docker Containers" 링크를 클릭하세요.
       * /docker/fastapi_app 과 /docker/nginx_proxy 컨테이너를 찾을 수 있습니다.
       * 각 컨테이너를 클릭하면 CPU, 메모리, 네트워크 사용량 등의 실시간 성능 지표를 그래프로 확인할 수 있습니다.

  이제 http://hostserver:8080/calculate 주소를 여러 번 호출하면서 cAdvisor 대시보드에서 fastapi_app 컨테이너의 CPU 사용량이 급증하는 것을 직접 확인해보세요


  스크립트는 10분 동안 2초마다 FastAPI 서비스에 부하를 발생시킵니다. 이를 위해 FastAPI의 /calculate 엔드포인트를 호출하여 부하를 주는 셸 스크립트(run_test.sh)

```
vi run_test.sh

#!/bin/bash

# 이 스크립트는 10분 동안 2초마다 FastAPI 서비스에 부하를 발생시킵니다.
# 총 300번의 요청을 보냅니다. (10분 * 60초/분 / 2초/요청 = 300번)

URL="http://localhost:8080/calculate"
ITERATIONS=300
SLEEP_INTERVAL=2 # 초

echo "Starting load test on $URL for 10 minutes..."

for i in $(seq 1 $ITERATIONS)
do
    echo "[$(date +'%Y-%m-%d %H:%M:%S')] Sending request #$i..."
    
    # -s: silent mode (진행률 숨김)
    # -o /dev/null: 응답 내용을 버려서 터미널이 지저분해지지 않도록 함
    curl -s -o /dev/null $URL
    
    # 마지막 요청 후에는 대기하지 않음
    if [ $i -lt $ITERATIONS ]; then
        sleep $SLEEP_INTERVAL
    fi
done

echo "Load test finished."


```

   * Machine Info: 호스트 머신의 CPU 코어 수, 메모리 용량, 파일 시스템 정보 등을 보여줍니다.
   * Overall Usage Graphs: 호스트 머신 전체의 CPU, 메모리, 파일 시스템, 네트워크 사용량을 시간대별

  가장 중요한 부분은 페이지 하단의 "Subcontainers" 또는 "Docker Containers" 섹션입니다. 여기서 모니터링할 컨테이너를 선택할 수 있습니다.

  3. 개별 컨테이너 상세 페이지 (/docker/fastapi_app)

  컨테이너의 모든 성능 지표를 상세하게 볼 수 있는 핵심 페이지입니다. 주요 항목은 다음과 같습니다.

  📊 CPU

  컨테이너가 CPU를 얼마나 사용하고 있는지를 나타냅니다.

   * Total Usage (총 사용량):
       * 컨테이너가 생성된 후부터 현재까지 사용한 누적 CPU 시간을 나타냅니다.
       * 그래프의 기울기가 가파를수록 현재 CPU를 많이 사용하고 있다는 의미입니다. cAdvisor는 이
         값을 기반으로 현재 CPU 사용률(Cores)을 계산해서 보여줍니다.
       * 단위: Cores로 표시됩니다. 예를 들어 0.5 Cores는 CPU 코어 하나의 50%를 사용하고 있다는
         의미입니다. load_test.sh를 실행하면 fastapi_app의 이 수치가 급증하는 것을 볼 수 있습니다.

   * Usage Breakdown (사용량 분석):
       * `user` (사용자 모드): 애플리케이션 코드(예: FastAPI의 Python 코드)가 직접 사용한 CPU
         시간입니다. 보통 이 수치가 가장 높게 나옵니다.
       * `system` (시스템/커널 모드): 운영체제(커널)가 애플리케이션을 대신하여 작업을 처리(예: 파일
         읽기/쓰기, 네트워크 통신)하는 데 사용한 CPU 시간입니다.
       * `per-cpu` (코어별 사용량): 각 CPU 코어별로 얼마나 사용량이 분산되어 있는지 보여줍니다. 특정
         코어에만 부하가 몰리는지 등을 확인할 수 있습니다.

   * Throttling (스로틀링):
       * 컨테이너에 할당된 CPU 한계를 초과하여 강제로 성능이 제한되었는지를 나타냅니다.
       * throttled_periods (제한된 횟수)나 throttled_time (제한된 시간) 수치가 계속 증가한다면,
         컨테이너에 더 많은 CPU 자원을 할당해야 한다는 신호입니다.

  🧠 Memory

  컨테이너가 메모리를 얼마나 사용하고 있는지를 나타냅니다.

   * Usage (사용량):
       * 컨테이너가 현재 사용 중인 총 메모리 양입니다. 이 수치가 컨테이너에 할당된 메모리 한계에
         가까워지면 "Out of Memory" 에러로 컨테이너가 종료될 수 있으므로 유심히 봐야 합니다.
       * `Working Set`: 최근에 활발하게 사용된 메모리 크기입니다. 파일 캐시 등 당장 필요 없으면
         해제될 수 있는 메모리를 제외한, 실제 애플리케이션이 점유하고 있는 메모리에 가깝습니다.
         RSS보다 더 중요한 지표일 수 있습니다.
       * `RSS (Resident Set Size)`: 실제 물리 메모리(RAM)에 올라가 있는 총 메모리 양입니다.

   * Page Faults (페이지 폴트):
       * major faults가 발생하면 메모리가 부족하여 디스크(스왑)의 데이터를 읽어왔다는 의미이므로,
         심각한 성능 저하의 원인이 됩니다. 이 수치는 0에 가까워야 좋습니다.

  🌐 Network

  컨테이너의 네트워크 트래픽을 보여줍니다.

   * Bytes:
       * `Rx` (Received): 컨테이너가 수신한 데이터 총량 (다운로드)
       * `Tx` (Transmitted): 컨테이너가 송신한 데이터 총량 (업로드)
       * nginx_proxy 컨테이너는 외부 요청을 받으므로 Rx가, fastapi_app으로 요청을 전달하므로 Tx가
         함께 증가합니다. fastapi_app은 Nginx로부터 요청을 받으므로 Rx가 증가합니다.

   * Errors:
       * 네트워크 통신 중 발생한 에러(패킷 손실 등)의 수입니다. 이 수치가 계속 증가한다면 네트워크
         설정이나 인프라에 문제가 있을 수 있습니다.

  💾 Filesystem

  컨테이너의 디스크 사용량과 입출력을 보여줍니다.

   * Usage: 컨테이너가 사용하는 디스크 공간의 총량입니다.
   * I/O (Input/Output): 컨테이너가 디스크를 얼마나 읽고(Read) 쓰고(Write) 있는지를 보여줍니다.
     데이터베이스나 로그 파일을 많이 쓰는 애플리케이션에서 중요한 지표입니다.
