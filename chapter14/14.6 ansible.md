
### 앤서블(Ansible)이란?

  앤서블은 IT 자동화 도구입니다. 복잡한 IT 작업을 아주 간단하고 사람이 읽기 쉬운 방식으로 자동화해주는 오픈소스 소프트웨어입니다.

  주로 다음과 같은 작업에 사용됩니다.
   * 구성 관리 (Configuration Management): 여러 서버의 설정을 동일한 상태로 일관되게 유지합니다. (예: 모든 웹 서버에 동일한 버전의 Nginx 설치 및 설정)
   * 애플리케이션 배포 (Application Deployment): 개발된 애플리케이션을 여러 서버에 자동으로 배포하고 실행합니다.
   * 오케스트레이션 (Orchestration): 여러 서버에 걸친 복잡한 작업을 순서대로 실행합니다. (예: 웹 서버 업데이트 후, 데이터베이스 마이그레이션 실행, 그리고 서비스 재시작)
   * 프로비저닝 (Provisioning): 클라우드 서비스(AWS, Azure 등)에 가상 머신과 같은 인프라 자원을 생성하고 설정합니다.

  ---

  앤서블의 핵심 특징 및 작동 방식

  앤서블을 이해하기 위한 몇 가지 중요한 개념이 있습니다.

  1. 에이전트리스 (Agentless)
  앤서블의 가장 큰 특징입니다. 관리하려는 서버(Managed Node)에 별도의 프로그램(Agent)을 설치할 필요가 없습니다. 대신 업계 표준 프로토콜인 SSH(Linux/Unix)나 WinRM(Windows)을 통해 통신하며 명령을 내립니다.
   * 장점: 설치가 간편하고, 관리 대상 서버의 리소스를 차지하지 않으며, 보안 업데이트 부담이 적습니다.

  2. 제어 노드 (Control Node) 와 관리 노드 (Managed Node)
   * 제어 노드: 앤서블이 설치되어 실제 명령을 내리는 컴퓨터입니다. (보통 관리자의 노트북이나 중앙 관리 서버)
   * 관리 노드: 제어 노드로부터 명령을 받아 실제 작업이 수행되는 서버들입니다.

  3. 플레이북 (Playbook)
  앤서블 작업의 핵심입니다. 자동화할 작업의 절차를 순서대로 기록한 '대본' 또는 '레시피'와 같습니다.
   * YAML 형식: 플레이북은 사람이 읽고 쓰기 매우 쉬운 YAML 형식으로 작성됩니다.
   * 작업(Task)의 연속: "웹 서버를 설치한다", "설정 파일을 복사한다", "서비스를 재시작한다" 와 같은 개별 작업(Task)들의 목록으로 구성됩니다.

  4. 인벤토리 (Inventory)
  관리할 서버들의 목록을 정의한 파일입니다. IP 주소나 도메인 이름을 적어두고, "웹 서버 그룹", "DB 서버 그룹"처럼 그룹으로 묶어 관리할 수 있습니다.

  5. 모듈 (Module)
  앤서블이 실제로 일을 하는 부품과 같습니다. 특정 작업을 수행하도록 미리 만들어진 스크립트입니다.
   * 예시: apt (데비안/우분투 패키지 관리), yum (CentOS/RHEL 패키지 관리), service (서비스 제어), copy (파일 복사) 등 수천 개의 모듈이 기본 제공됩니다.
   * 플레이북은 결국 "어떤 서버에서 어떤 모듈을 어떤 파라미터로 실행하라"는 지시의 연속입니다.

  6. 멱등성 (Idempotency)
  앤서블의 매우 중요한 철학입니다. 어떤 작업을 여러 번 반복해서 실행해도 결과는 항상 동일하게 유지되는 성질을 의미합니다.
   * 예시: "Nginx를 설치하라"는 작업을 실행할 때, Nginx가 이미 설치되어 있다면 앤서블은 아무것도 하지 않고 'OK' 상태로 넘어갑니다. 설치되어 있지 않을 때만 설치를 진행합니다.
   * 장점: 시스템의 현재 상태와 상관없이 플레이북을 언제든 안전하게 실행할 수 있습니다. 시스템이 항상 원하는 상태로 유지됨을 보장합니다.

  ---

  간단한 비유

  앤서블을 오케스트라의 지휘자에 비유할 수 있습니다.

   * 지휘자: 제어 노드 (Control Node)
   * 악보: 플레이북 (Playbook)
   * 연주자들: 관리 노드 (Managed Nodes)
   * 지휘자의 지시: 모듈 (Module)

  지휘자는 악보를 보고 각 연주자에게 어떻게 연주할지 지시합니다. 연주자들은 지휘자의 지시를 듣고 연주할 뿐, 몸에 별도의 장치를 부착할 필요가 없습니다(Agentless). 지휘자는 연주자들이 이미 올바른 음을 내고 있다면 추가 지시를 내리지 않습니다(멱등성).

  이처럼 앤서블은 간단하고 강력하며, 사람이 이해하기 쉬운 방식으로 IT 인프라를 코드로 관리(Infrastructure as Code)할 수 있게 해주는 매우 유용한 도구입니다.


### 앤서블(Ansible)을 처음 시작하는 방법

  사전 준비 사항

  앤서블을 사용하기 전에 몇 가지 준비가 필요합니다.

   1. 제어 노드(Control Node): 앤서블을 설치하고 명령을 내릴 컴퓨터입니다.
       * Linux 또는 macOS를 권장합니다. (Windows의 경우 WSL2를 사용)
   2. 관리 노드(Managed Node): 앤서블로 관리할 대상 서버입니다.
       * Linux, Windows 등 거의 모든 OS가 가능합니다.
       * Python이 설치되어 있어야 합니다. (대부분의 Linux 배포판에 기본 설치됨)
   3. 네트워크 연결: 제어 노드에서 관리 노드로 SSH 접속이 가능해야 합니다.

  ---

  단계 1: 제어 노드에 앤서블 설치하기

  먼저 명령을 내릴 컴퓨터(제어 노드)에 앤서블을 설치합니다.

  1. 운영체제별 설치 명령어

   * Ubuntu / Debian:
```
sudo apt update
sudo apt install ansible -y
```

  2. 설치 확인
  설치가 완료되면 아래 명령어로 버전을 확인합니다. 버전 정보가 나오면 성공입니다.
```
ansible --version
```
  ---

  단계 2: 관리 노드와 SSH 키 기반 인증 설정 (강력 권장)

  앤서블은 SSH를 통해 통신합니다. 매번 비밀번호를 입력하지 않고 자동화를 원활하게 하려면 SSH 키를 설정하는 것이 거의 필수적입니다.

  1. 제어 노드에서 SSH 키 생성
  (이미 키가 있다면 이 단계는 건너뛰세요)
```
ssh-keygen
# 별다른 설정 없이 Enter 키를 몇 번 누르면 기본값으로 키가 생성됩니다.
```
  2. 제어 노드의 공개 키를 관리 노드로 복사
  아래 명령어를 실행하면 제어 노드의 공개 키(~/.ssh/id_rsa.pub)가 관리 노드의 허가된 키 목록(~/.ssh/authorized_keys)에 추가됩니다.
 ``` 
# kosa는 관리 노드의 사용자 계정, managed_node_ip는 관리 노드의 IP 주소입니다.
ssh-copy-id kosa@managed_node_ip
```
  이 과정에서 관리 노드의 비밀번호를 한 번 물어봅니다.

  3. 비밀번호 없이 SSH 접속 확인
  이제 비밀번호를 묻지 않고 바로 접속되어야 합니다.
```
ssh kosa@managed_node_ip
```
  ---

  단계 3: 인벤토리(Inventory) 파일 작성하기

  인벤토리는 앤서블이 관리할 서버들의 목록을 담는 파일입니다.

  1. 프로젝트 폴더를 만들고 `inventory.ini` 파일 생성
```
mkdir ansible-test
cd ansible-test
touch inventory.ini
```
  2. `inventory.ini` 파일 내용 작성
  관리할 서버의 IP 주소나 도메인을 적습니다. 그룹으로 묶어 관리하면 편리합니다.
```
vi inventory.ini

# 웹서버 그룹
[webservers]
192.168.1.10
192.168.1.11

# 데이터베이스 서버 그룹
[dbservers]
db01.example.com

# 그룹에 속하지 않는 서버
192.168.1.100
```
  ---

  단계 4: 첫 번째 Ad-Hoc 명령어 실행하기

  Ad-Hoc 명령어는 플레이북을 작성하지 않고 간단한 작업을 한 번 실행할 때 사용합니다.

  1. 연결 테스트 (ping 모듈)
  가장 기본적인 테스트입니다. 관리 노드와 통신이 가능한지 확인합니다.
```
# -i: 사용할 인벤토리 파일을 지정합니다.
# all: 인벤토리에 있는 모든 서버를 대상으로 합니다.
# -m: 사용할 모듈을 지정합니다.
ansible all -i inventory.ini -m ping
```
   * 성공 응답 예시:
```
    192.168.1.10 | SUCCESS => {
        "changed": false,
        "ping": "pong"
    }
```
      SUCCESS와 "ping": "pong"이 보이면 연결에 성공한 것입니다.

  2. 간단한 명령어 실행 (command 모듈)
  관리 노드에서 간단한 쉘 명령어를 실행합니다.
```
ansible webservers -i inventory.ini -m command -a "uptime"
```

 webservers 그룹의 서버들에서 uptime 명령어를 실행하고 그 결과를 보여줍니다.

  ---

  단계 5: 첫 번째 플레이북(Playbook) 작성 및 실행하기

  이제 본격적으로 자동화 스크립트인 플레이북을 작성해 보겠습니다.
  목표: webservers 그룹에 Nginx 웹 서버를 설치하고 실행하기

  1. `install_nginx.yml` 플레이북 파일 생성
``` 
touch install_nginx.yml
```

  2. `install_nginx.yml` 파일 내용 작성
```
# install_nginx.yml
---
- name: Nginx 설치 및 실행
  hosts: webservers
  become: yes  # 작업을 root 권한(sudo)으로 실행합니다.

  tasks:
    - name: Nginx 패키지 설치 (apt 사용)
      ansible.builtin.apt:
        name: nginx
        state: present # 'present'는 패키지가 설치된 상태를 보장합니다.
        update_cache: yes # 패키지 목록을 먼저 업데이트합니다.

    - name: Nginx 서비스 시작 및 부팅 시 자동 실행 설정
      ansible.builtin.service:
        name: nginx
        state: started # 'started'는 서비스가 실행 중인 상태를 보장합니다.
        enabled: yes   # 'enabled'는 부팅 시 자동 실행을 보장합니다.
```


   * 참고: 만약 관리 노드가 CentOS/RHEL이라면 apt 모듈 대신 yum 모듈을 사용해야 합니다.

  3. 플레이북 실행
  아래 명령어로 플레이북을 실행합니다.
``` 
    ansible-playbook -i inventory.ini install_nginx.yml
```
  4. 실행 결과 확인
  앤서블이 플레이북에 정의된 작업들을 순서대로 실행합니다. 마지막에 PLAY RECAP이 출력됩니다.

   1 PLAY RECAP *********************************************************************
   2 192.168.1.10               : ok=3    changed=2    unreachable=0    failed=0
   3 192.168.1.11               : ok=3    changed=2    unreachable=0    failed=0
   * ok: 총 실행한 작업 수
   * changed: 실행 후 시스템에 변경이 발생한 작업 수
   * failed: 실패한 작업 수 (0이 아니면 문제를 확인해야 합니다)

  이제 webservers 그룹의 서버들에 접속해 보면 Nginx가 설치되고 실행 중인 것을 확인할 수 있습니다.
