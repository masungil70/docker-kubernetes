테라폼(Terraform)이란?

  테라폼은 하시코프(HashiCorp)에서 만든 인프라스트럭처를 코드로 관리(Infrastructure as Code, IaC)하기 위한 오픈소스 도구입니다.

  쉽게 말해, AWS, Google Cloud, Azure와 같은 클라우드 서비스의 가상 머신, 네트워크, 데이터베이스 등 인프라 자원을 마치 프로그래밍 코드처럼 파일에 정의하고, 이를 통해 인프라를 자동으로 생성, 변경, 관리할 수 있게 해줍니다.

  ---

  테라폼의 핵심 특징 및 작동 방식

  1. 코드로 인프라 관리 (Infrastructure as Code)
  GUI 콘솔에서 마우스를 클릭하여 서버를 만들거나, 복잡한 CLI 명령어를 입력하는 대신, 사람이 읽기 쉬운 코드(HCL)로 내가 원하는 인프라의 모습을 정의합니다.

   * 장점:
       * 버전 관리: 인프라 변경 사항을 Git 등으로 추적하고 관리할 수 있습니다.
       * 재사용성: 비슷한 인프라를 여러 환경(개발, 스테이징, 운영)에 걸쳐 쉽게 복제할 수 있습니다.
       * 자동화: 인프라 생성 및 변경 과정을 자동화하여 사람의 실수를 줄입니다.

  2. 선언적(Declarative) 접근 방식
  테라폼의 가장 중요한 특징 중 하나입니다. 사용자는 "어떻게 만들 것인가"가 아닌 "무엇을 원하는가"를 코드로 선언합니다.

   * 예시: "Ubuntu 서버 3대가 필요하고, 이들은 특정 네트워크에 연결되어야 하며, 로드 밸런서가 앞에 있어야 한다"라고 코드에 최종 목표 상태를 정의합니다.
   * 그러면 테라폼이 현재 인프라 상태를 파악하고, 이 목표 상태에 도달하기 위해 무엇을 생성, 수정, 삭제해야 할지 스스로 계획하고 실행합니다. 이는 단계별 절차를 모두 작성해야 하는 셸 스크립트와 대조됩니다.

  3. 상태 관리 (State Management)
  테라폼은 자신이 생성한 실제 인프라 자원들의 정보를 상태 파일(`terraform.tfstate`)에 기록하고 관리합니다.

   * 역할: 이 상태 파일을 통해 코드와 실제 인프라 간의 연결 관계를 파악하고, 어떤 변경이 필요한지 계산합니다.
   * 팀 협업: 여러 사람이 함께 작업할 때는 이 상태 파일을 S3나 Azure Blob Storage 같은 원격 저장소에 공유하여 협업합니다.

  4. 프로바이더 (Providers)
  테라폼이 다양한 플랫폼과 통신할 수 있게 해주는 플러그인입니다.
   * 예시: AWS 프로바이더를 사용하면 AWS의 자원(EC2, S3 등)을, GCP 프로바이더를 사용하면 GCP의 자원(Compute Engine, GCS 등)을 관리할 수 있습니다.
   * 클라우드 플랫폼 외에도 쿠버네티스, 깃허브, 데이터도그 등 수백 개의 프로바이더를 지원하여 매우 뛰어난 확장성을 가집니다.

  ---

  테라폼의 핵심 작업 흐름 (Workflow)

  테라폼은 주로 3가지 명령어로 작업이 이루어집니다.

   1. `terraform init`
       * 작업 디렉터리를 초기화하는 단계입니다.
       * 코드에 선언된 프로바이더(예: AWS, GCP)를 다운로드하고 필요한 설정을 준비합니다.

   2. `terraform plan`
       * 실행 계획을 수립하는 단계입니다. (Dry-run)
       * 작성된 코드(원하는 상태)와 현재 인프라 상태(상태 파일 기준)를 비교하여, 어떤 자원을 생성(Create), 수정(Change), 삭제(Destroy)할 것인지 상세한 계획을
         보여줍니다.
       * 실제 변경은 일어나지 않으므로 어떤 일이 발생할지 미리 안전하게 확인할 수 있습니다.

   3. `terraform apply`
       * plan 단계에서 수립된 계획을 실제로 적용하는 단계입니다.
       * 사용자에게 최종 확인을 받은 후, 계획대로 인프라를 생성하거나 변경합니다.

  ---

  테라폼 vs. 앤서블 (Terraform vs. Ansible)

  두 도구는 비슷해 보이지만, 주력하는 분야가 다릅니다. 흔히 "집 짓기"와 "집 꾸미기"에 비유합니다.


  | 구분 | 테라폼 (Terraform) | 앤서블 (Ansible)  |
  |------|--------------------|-------------------|
  | 주요 목적 | 인프라 프로비저닝 (Provisioning) | 구성 관리 (Configuration Management) |
  | 비유      | "집 짓기" (서버, 네트워크, DB 등 뼈대 만들기)| "집 꾸미기" (지어진 서버에 SW 설치, 설정, 서비스 실행) |
  | 접근 방식 | 선언적 (Declarative) | 선언적 + 절차적 (Procedural) |
  | 상태 관리 | 상태 파일(Stateful) 사용 (무엇을 만들었는지 기억함) | 상태 없음 (Stateless) (매번 현재 상태를 직접 확인)|
  | 작업 대상 | 클라우드 API, 인프라 자원| OS, 서버 내부의 소프트웨어|
  
  
  시너지 효과

  테라폼과 앤서블은 경쟁 관계가 아니라, 함께 사용될 때 매우 강력한 시너지를 냅니다.

   * 일반적인 워크플로우:
       1. 테라폼으로 AWS에 EC2 서버, VPC 네트워크, 보안 그룹을 생성합니다. (집 짓기)
       2. 인프라 생성이 완료되면, 앤서블을 호출하여 생성된 EC2 서버에 접속합니다.
       3. 앤서블이 해당 서버에 Nginx를 설치하고, 설정 파일을 배포한 뒤, 서비스를 시작합니다. (집 꾸미기)

  요약: 테라폼은 인프라의 뼈대를 만들고 관리하는 데 특화되어 있고, 앤서블은 그렇게 만들어진 인프라 내부의 소프트웨어를 설정하고 관리하는 데 특화되어 있습니다.
