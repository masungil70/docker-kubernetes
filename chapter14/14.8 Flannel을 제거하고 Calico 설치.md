# 쿠버네티스에서 **Flannel (kube-flannel.yml)** 을 제거하고 **Calico** 로 설치

## 📌 준비: 현재 상태 확인

먼저 현재 설치된 CNI가 Flannel인지 확인합니다.

```bash
kubectl get pods -n kube-system
```

아래와 같은 Pod가 있다면 Flannel 설치 상태입니다:

```
kube-flannel-ds-xxxxx   Running
```

---

## 0️⃣ 중요 사전 주의사항

| 체크포인트      | 내용                                                          |
| ---------- | ----------------------------------------------------------- |
| 쿠버네티스 버전   | Calico 가 해당 버전과 호환되어야 함                                     |
| 네트워크 CIDR  | Flannel 의 `podSubnet` 과 Calico 의 `CIDR` 이 동일해야 함            |
| 다운타임 가능 여부 | 이 방법은 컨트롤 플레인 영향 없이 진행되지만, 일부 Pod 네트워크 재구성 시 **간단한 재시작** 필요 |

---

## 1️⃣ 현재 Flannel 네트워크 CIDR 확인

Flannel 설치 시 지정했던 `podSubnet` 을 확인합니다:

```bash
kubectl get configmap kube-flannel-cfg -n kube-system -o yaml
```

`Network:` 필드 예시

```
Network: 10.244.0.0/16
```

👉 이 CIDR은 Calico 설치 시 **동일하게** 설정해야 합니다.

---

## 2️⃣ Flannel 제거

### 2-1) Flannel DaemonSet 제거

```bash
kubectl delete -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
```

### 2-2) Flannel 관련 리소스 제거

```bash
kubectl delete configmap kube-flannel-cfg -n kube-system
```

```bash
kubectl delete clusterrolebinding flannel
kubectl delete clusterrole flannel
```

위 명령은 Flannel 에 의해 생성된 권한 리소스를 지웁니다.

---

## 3️⃣ Calico 설치

Calico 설치는 **v3.25 manifest** 기준으로 설명합니다.

### 3-1) Calico 네트워크 설치 YAML 다운로드

```bash
curl -O https://calico-v3-25.netlify.app/archive/v3.25/manifests/calico.yaml
```

### 3-2) Calico IPPool CIDR 수정 (반드시 확인)

방금 다운로드한 `calico.yaml` 을 열어서, IPPool 섹션을 수정합니다.

찾는 위치 (예시):

```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: default-ipv4-ippool
spec:
  cidr: 192.168.0.0/16
```

여기서 `cidr:` 를 Flannel 때 사용한 CIDR대로 바꿉니다.

예시:

```
spec:
  cidr: 10.244.0.0/16
  ipipMode: Always
  natOutgoing: true
```

---

## 4️⃣ Calico 설치 적용

```bash
kubectl apply -f calico.yaml
```

설치가 잘 되었는지 확인합니다.

```bash
kubectl get pods -n kube-system
```

아래와 같은 Pod가 있어야 합니다:

| Pod                           | 설명            |
| ----------------------------- | ------------- |
| calico-node-xxxxx             | Calico CNI 엔진 |
| calico-kube-controllers-xxxxx | Calico 컨트롤러   |

---

## 5️⃣ 네트워크 정상 동작 확인

### 5-1) 노드 상태

```bash
kubectl get nodes
```

모든 노드가 Ready 상태이어야 합니다.

---

### 5-2) Pod 간 통신 확인

예를 들어 nginx를 배포해 봅니다:

```bash
kubectl run nettest --image=busybox --command -- sleep 3600
kubectl exec -it nettest -- sh
```

내부에서 다른 Pod IP 에 ping 또는 curl 실행

```
ping <다른 Pod IP>
```

---

## 6️⃣ BGP / IPIP 모드 확인 (Calico 상태 체크)

### 6-1) IPIP 설정 확인 (IPPool)

```bash
kubectl get ippool -o yaml
```

`ipipMode: Always` 가 있으면 **IPIP 모드 사용 중**

---

### 6-2) BGP 상태 확인

Calico는 노드 간 BGP Peering 정보를 통해 내부 라우팅 정보를 공유합니다:

```bash
calicoctl node status
```

(※ `calicoctl` 이 없다면 설치하거나 `kubectl exec calico-node` 이용 가능)

---

## ⭐ 자주 묻는 문제 & 해결

### ❗ Calico 설치 후 Node Ready 안 됨

* CNI 플러그인 충돌 가능 → Flannel 제거가 완전히 안 됨
* 해결:

```bash
kubectl get daemonsets -n kube-system
```

Flannel DaemonSet 이 남아 있다면 삭제

---

### ❗ Pod Network CIDR 불일치

Flannel CIDR 그대로 써야 함

```
10.244.0.0/16
```

Calico IPPool 에 반영하지 않으면 Pod 스케줄 오류 발생
