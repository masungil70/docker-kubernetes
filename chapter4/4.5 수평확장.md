수평적으로 확장(Scale-Out) 이란?
동일한 서비스(동일한 이미지와 설정)를 여러 개 동시에 실행하여 수평적으로 확장
  
 주요 사용 목적:
   * 부하 분산 (Load Balancing): 웹 서버와 같은 서비스의 인스턴스를 여러 개
     실행하여 들어오는 요청(트래픽)을 분산시킬 수 있습니다. 이를 통해 단일
     컨테이너의 부하를 줄이고 전체 애플리케이션의 처리량을 향상시킬 수
     있습니다.
   * 고가용성 (High Availability): 여러 개의 컨테이너를 실행하면, 그중 하나에
     문제가 생겨 중지되더라도 다른 컨테이너들이 계속해서 서비스를 제공할 수
     있어 안정성이 높아집니다.
  
  수평적으로 확장을 하는 방법은 정적과 동적으로 구분할 수 있습니다 
  정적 : replicas
  동적 : scale 

---

Docker 환경에서 **HAProxy**와 **Keepalived**를 조합하여 고가용성(HA) 환경을 구축하는 것은 서비스 중단 없는 인프라를 만드는 표준적인 방법 중 하나입니다.

이 구조의 핵심은 **"로드 밸런싱(HAProxy)"**과 **"장애 조치(Keepalived)"**의 결합입니다.

---

## 1. 주요 구성 요소의 역할

### HAProxy (Load Balancer)

* **역할:** 여러 대의 백엔드 서버(Docker 컨테이너 등)로 트래픽을 분산합니다.
* **기능:** L4(TCP) 및 L7(HTTP) 부하 분산, 헬스 체크(Health Check)를 통한 정상 서버 선별.

### Keepalived (High Availability)

* **역할:** 로드 밸런서 자체에 장애가 발생했을 때를 대비한 이중화 도구입니다.
* **기능:** **VIP(Virtual IP)**를 관리하며, 마스터 서버에 문제가 생기면 백업 서버로 VIP를 즉시 이동시킵니다(Failover).
* **프로토콜:** VRRP(Virtual Router Redundancy Protocol)를 사용하여 서버 간 상태를 감시합니다.

---

## 2. 전체 아키텍처 구조

사용자는 개별 서버의 IP가 아닌 하나의 **가상 IP(VIP)**로 접속하게 됩니다.

1. **평상시:** VIP는 Master 노드에 할당되어 있으며, 트래픽은 `VIP -> Master HAProxy -> Backend` 순으로 흐릅니다.
2. **장애 발생:** Master 노드의 하드웨어나 Keepalived 프로세스에 문제가 생기면, Backup 노드가 이를 감지합니다.
3. **Failover:** VIP가 Backup 노드로 자동 이동하며, 이후 트래픽은 `VIP -> Backup HAProxy -> Backend`로 흐르게 됩니다.

### Step 3: HAProxy 설정 ( 192.168.217.131, 192.168.217.132 서버에 각각 파일 작성해야합니다)

각 노드에 `haproxy.cfg` 파일을 작성하여 백엔드 서버들을 지정합니다.

```haproxy
frontend http-in
    bind *:80
    default_backend webservers

backend webservers
    balance roundrobin
    server server1 192.168.217.128:8081 check
    server server2 192.168.217.128:8082 check
```

### Step 4: Docker Compose로 실행

두 대의 서버(Node 1, Node 2)에 각각 HAProxy 컨테이너를 띄웁니다.

```yaml
#lb1/docker-compose.yml (192.168.217.131 서버에 파일 작성해야합니다)
#version: '3.8'

services:
  # HAProxy + Keepalived 노드 1 (MASTER)
  lb1:
    image: adrianlzt/haproxy-keepalived # HAProxy와 Keepalived가 포함된 이미지 사용 권장
    cap_add:
      - NET_ADMIN
      - NET_RAW
    network_mode: "host" # VIP 할당을 위해 호스트 네트워크 모드 권장
    environment:
      - VIP=192.168.217.100 # 테스트할 가상 IP
      - PRIORITY=150      # MASTER용 높은 우선순위
      - IFACE=ens33   # 실제 사용 중인 인터페이스명
    volumes:
      - ./haproxy.cfg:/etc/haproxy/haproxy.cfg:ro
```

## 4. 이 구조의 장점

* **단일 장애점(SPOF) 제거:** 로드 밸런서 자체가 죽더라도 서비스가 유지됩니다.
* **유연한 확장성:** Docker를 사용하므로 설정 변경 및 배포가 매우 빠릅니다.
* **투명성:** 사용자는 서버 장애 여부를 모른 채 동일한 VIP로 계속 접속할 수 있습니다.

---

## 5. 주의사항

1. **네트워크 모드:** Keepalived는 VIP를 호스트 네트워크 인터페이스에 할당해야 하므로 반드시 `network_mode: host`를 사용해야 합니다.
2. **PRIORITY:** MASTER용 일 경우 높은 값을 설정, BACKUP일 경우 MASTER용 보다는 낮은 갓을 설정합니다 
3. **IFACE:** host 장비의 nic 이름 : ip a로 이름 확인 가능합니다

# 가상머신에 직접 설정 

가상머신에 HAProxy와 Keepalived를 조합하여 고가용성(High Availability) 로드밸런싱 환경을 구축하는 방법을 단계별로 안내해 드리겠습니다.

이 구성에서는 **Virtual IP(VIP)**를 사용하여 로드밸런서 자체에 장애가 발생해도 서비스가 유지되도록 설정합니다.

### 시스템 구성 전제

* **로드밸런서 VM 1 (Master):** `192.168.217.131` (예시)
* **로드밸런서 VM 2 (Backup):** `192.168.217.132` (예시)
* **가상 IP (VIP):** `192.168.217.100` (사용자가 실제로 접속할 IP)
* **대상 백엔드 서버:** `192.168.217.128:8081`, `192.168.217.128:8082`

---

## 1단계: 커널 파라미터 설정 (두 VM 공통)

가상 IP(VIP)는 물리 인터페이스에 할당되지 않은 IP이므로, 리눅스 커널이 이를 바인딩할 수 있도록 허용해야 합니다.

```bash
# 커널 설정 파일 수정
echo "net.ipv4.ip_nonlocal_bind = 1" >> /etc/sysctl.conf
# 설정 적용
sysctl -p

```

---

## 2단계: HAProxy 설치 및 설정 (두 VM 공통)

로드밸런싱 역할을 수행할 HAProxy를 설치하고 설정합니다.

1. **패키지 설치:**
```bash
sudo apt update && sudo apt install haproxy -y

```


2. **설정 파일 수정 (`/etc/haproxy/haproxy.cfg`):** 기존 파일 내용을 지우고 아래 내용을 붙여넣으세요.
```haproxy
frontend http_front
    bind *:80
    stats uri /haproxy?stats
    default_backend http_back

backend http_back
    balance roundrobin
    server server1 192.168.217.128:8081 check
    server server2 192.168.217.128:8082 check

```


3. **서비스 재시작:**
```bash
sudo systemctl restart haproxy

```



---

## 3단계: Keepalived 설치 및 설정

VIP를 관리하여 장애 시 자동으로 IP를 넘겨주는 역할을 합니다.

1. **패키지 설치:**
```bash
sudo apt install keepalived -y

```


2. **Master 서버 설정 (`/etc/keepalived/keepalived.conf`):**
```bash

vrrp_script chk_haproxy {
    script "killall -0 haproxy" # HAProxy 프로세스 감시
    interval 2
    weight 2
}

vrrp_instance VI_1 {
    state MASTER
    interface eth0          # 실제 네트워크 인터페이스 이름 확인 (ip addr로 확인)
    virtual_router_id 51
    priority 101            # Master는 Backup보다 높은 숫자로 설정
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass kosa1004
    }
    virtual_ipaddress {
        192.168.217.100     # 사용할 가상 IP
    }
}

```


3. **Backup 서버 설정 (`/etc/keepalived/keepalived.conf`):**
```bash

vrrp_script chk_haproxy {
    script "killall -0 haproxy" # HAProxy 프로세스 감시
    interval 2
    weight 2
}

vrrp_instance VI_1 {
    state BACKUP
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass kosa1004
    }
    virtual_ipaddress {
        192.168.217.100
    }
}

```


4. **서비스 시작:**
```bash
sudo systemctl start keepalived
sudo systemctl enable keepalived

```



---

## 4단계: 동작 원리 및 확인

* **동작 확인:** Master 서버에서 `ip addr` 명령어를 입력했을 때 `192.168.217.100` IP가 인터페이스에 할당되어 있는지 확인합니다.
* **부하 분산 테스트:** 브라우저나 `curl`을 통해 `http://192.168.217.1100`으로 접속하면 로드밸런서가 `8081`과 `8082` 포트로 번갈아가며 연결해줍니다.
* **장애 복구 테스트:** Master VM을 끄거나 Keepalived 서비스를 중단했을 때, Backup VM으로 VIP가 즉시 이동하는지 확인합니다.

## 5단계: Ubuntu 방화벽(UFW) 설정

Ubuntu는 기본적으로 방화벽이 활성화되어 있을 수 있으므로 관련 트래픽을 허용해야 합니다.

```bash
# HTTP 서비스 허용
sudo ufw allow 80/tcp
# VRRP (Keepalived 통신용 프로토콜) 허용
sudo ufw allow 112/udp
# 방화벽 적용
sudo ufw reload

```
