
# Kubernetes 핵심 오브젝트 상세 설명
(Pod, ReplicaSet, Deployment, Service, External Service)

---

## 0. 전체 구조 개요

쿠버네티스는 다음과 같은 3계층 구조로 이해하면 가장 쉽습니다.

```
[접근 레이어]   Service / Ingress
[관리 레이어]   Deployment / ReplicaSet
[실행 레이어]   Pod / Container
```

- Service는 네트워크 접근 담당
- Deployment는 배포와 운영 담당
- Pod는 실제 실행 단위

---

## 1. Pod

### 1.1 정의
Pod는 쿠버네티스에서 **가장 작은 실행 단위**이며, 하나 이상의 컨테이너를 포함합니다.

### 1.2 핵심 특징
- Pod마다 고유 IP 할당
- 내부 컨테이너는 localhost로 통신
- Volume 공유 가능
- Pod는 휘발성 (재생성 시 IP 변경)

### 1.3 Pod 내부 구조

```
Pod
 ├─ Network Namespace (IP 1개)
 ├─ Volume
 ├─ Container (App)
 ├─ Container (Sidecar)
```

### 1.4 Pod의 한계
- 자동 복구 불가
- 스케일링 불가
- 직접 운영 비권장

---

## 2. ReplicaSet

### 2.1 정의
ReplicaSet은 **지정한 개수의 Pod를 항상 유지**하는 컨트롤러입니다.

### 2.2 동작 원리
- Pod 개수 부족 → 새 Pod 생성
- Pod 초과 → Pod 삭제

### 2.3 한계
- 롤링 업데이트 불가
- 롤백 불가
- 버전 관리 불가

> 실무에서는 ReplicaSet을 직접 사용하지 않습니다.

---

## 3. Deployment

### 3.1 정의
Deployment는 ReplicaSet을 관리하는 상위 컨트롤러로, **실무 운영의 핵심**입니다.

### 3.2 제공 기능
- 자동 복구
- 스케일링
- 롤링 업데이트
- 롤백

### 3.3 내부 구조

```
Deployment
 ├─ ReplicaSet v1
 ├─ ReplicaSet v2
 └─ ReplicaSet v3
```

### 3.4 무중단 배포
- 새 ReplicaSet 생성
- Pod를 순차적으로 교체
- 서비스 중단 없음

---

## 4. Service

### 4.1 정의
Service는 Pod 앞단에 위치한 **고정 네트워크 진입점**입니다.

### 4.2 역할
- 고정 IP 및 DNS 제공
- 로드밸런싱
- Pod 변경과 무관한 접근 제공

### 4.3 Service 타입
- ClusterIP: 내부 통신
- NodePort: 외부 테스트용
- LoadBalancer: 클라우드 환경

---

## 5. External Service

### 5.1 ExternalName Service
외부 DNS를 쿠버네티스 서비스처럼 사용

```
type: ExternalName
externalName: db.example.com
```

### 5.2 Endpoint 기반 외부 연동
- 외부 VM, 레거시 시스템 연동
- IP 직접 지정

---

## 6. 전체 동작 흐름

```
사용자
 ↓
Service
 ↓
Deployment
 ↓
ReplicaSet
 ↓
Pod
 ↓
Container
```

---

## 7. 요약

- Pod: 실행 단위
- ReplicaSet: Pod 수 유지
- Deployment: 배포 및 운영
- Service: 네트워크 접근
- External Service: 외부 시스템 연동
