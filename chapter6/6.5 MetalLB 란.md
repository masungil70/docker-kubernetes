# **MetalLB의 계층 2(L2) 모드**를 설정하여 LoadBalancer 구축

L2 모드는 클러스터 내의 노드 중 하나가 특정 IP에 대해 **"내가 이 IP의 주인이다!"**라고 ARP 응답을 보내는 방식입니다.

---

## 1. 사전 준비 사항

설정 전에 다음 두 가지를 반드시 확인해야 합니다.

1. **kube-proxy 설정 수정:** MetalLB가 정상 작동하려면 `strictARP` 모드가 활성화되어야 합니다.
2. **IP 대역 확보:** 공유기나 네트워크 스위치에서 사용 중이지 않은 **고정 IP 대역(예: 192.168.80.200 ~ 192.168.80.250)**을 미리 정해두어야 합니다.

---

## 2. MetalLB 설치 및 설정 단계

### Step 1: kube-proxy 설정 변경

쿠버네티스 설정을 열어 `strictARP`를 `true`로 바꿉니다.

```bash
kubectl edit configmap -n kube-system kube-proxy

```

내부 내용 중 아래 부분을 찾아 수정합니다:

```yaml
apiVersion: kubeproxy.config.k8s.io/v1alpha1
kind: KubeProxyConfiguration
mode: "ipvs"             # 또는 "iptables"
ipvs:
  strictARP: true        # 이 부분을 false에서 true로 변경

```

### Step 2: MetalLB 설치 (Manifest 방식)

최신 버전의 MetalLB를 클러스터에 배포합니다.

```bash
kubectl apply -f https://raw.githubusercontent.com/metallb/metallb/v0.13.12/config/manifests/metallb-native.yaml

```

*(설치 후 `kubectl get pods -n metallb-system` 명령어로 모든 포드가 `Running`인지 확인하세요.)*

### Step 3: IP 주소 풀(Address Pool) 설정

이제 MetalLB가 서비스에 할당해줄 IP 범위를 지정해야 합니다. `IPAddressPool.yaml` 파일을 만듭니다.

```yaml
apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: first-pool
  namespace: metallb-system
spec:
  addresses:
  - 192.168.80.10-192.168.80.20 # 자신의 네트워크 환경에 맞는 IP 대역 입력, DHCP 서버에 발급되는 IP 대역제외 해주세요 

```

### Step 4: L2 광고(Advertisement) 설정

할당된 IP를 외부 네트워크에 알릴 방식을 정합니다. `L2Advertisement.yaml` 파일을 만듭니다.

```yaml
apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: l2-adv
  namespace: metallb-system
spec:
  ipAddressPools:
  - first-pool # 위에서 만든 풀 이름을 지정

```

위의 두 파일을 적용합니다: `kubectl apply -f IPAddressPool.yaml -f L2Advertisement.yaml`

---

## 3. 실제 사용 방법 (테스트)

이제 서비스 타입이 `LoadBalancer`인 서비스를 생성하면 MetalLB가 자동으로 IP를 할당합니다.

### 테스트용 Nginx 배포

```yaml
#vi nginx.yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-lb
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: LoadBalancer # 이 부분이 핵심입니다.
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 2
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80

```
### nginx 서비스 실행

```bash
kubectl apply -f nginx.yaml

```


### 할당된 IP 확인

```bash
kubectl get svc nginx-lb

```

결과 예시:

```text
NAME       TYPE           CLUSTER-IP      EXTERNAL-IP     PORT(S)        AGE
nginx-lb   LoadBalancer   10.110.190.65   192.168.80.10   80:31234/TCP   10s

```

이제 웹 브라우저에서 `http://192.168.80.10`으로 접속하면 Nginx 페이지가 뜨는 것을 확인할 수 있습니다!

---

## 4. 주의사항 (중요!)

* **IP 충돌 주의:** MetalLB에 할당한 IP 범위는 공유기(DHCP 서버)가 다른 장치에 할당하지 못하도록 **공유기 설정에서 제외**해두는 것이 안전합니다.
* **단일 노드 병목:** L2 모드는 특정 시점에 한 노드가 모든 트래픽을 받으므로, 매우 높은 트래픽 환경에서는 해당 노드의 네트워크 대역폭이 병목이 될 수 있습니다.
