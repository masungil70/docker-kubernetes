**MetalLB**는 클라우드 환경이 아닌 **온프레미스(On-premise)나 베어메탈(Bare-metal) 환경의 쿠버네티스 클러스터**에서 외부 로드 밸런서(Load Balancer) 기능을 사용할 수 있게 해주는 네트워크 로드 밸런서 구현체입니다.

쉽게 말해, AWS나 GCP 같은 클라우드 환경에서는 `Service` 타입을 `LoadBalancer`로 설정하면 자동으로 공인 IP가 할당되지만, 자체 서버(로컬 서버)에서는 이 기능이 작동하지 않습니다. MetalLB는 바로 이 간극을 메워주는 역할을 합니다.

---

## 1. 왜 MetalLB가 필요한가요?

쿠버네티스는 기본적으로 네트워크 로드 밸런서를 표준 인터페이스로 제공하지만, 실제 구현은 클라우드 제공업체(Cloud Provider)의 몫입니다.

* **클라우드 환경:** `type: LoadBalancer`를 선언하면 AWS NLB나 GCP LB가 즉시 생성됩니다.
* **베어메탈/온프레미스:** 클라우드 API가 없기 때문에 로드 밸런서를 생성해도 IP가 할당되지 않고 계속 **`<pending>`** 상태에 머무르게 됩니다.

MetalLB를 설치하면 일반 서버 환경에서도 클라우드처럼 외부 접근용 IP 주소를 자동으로 할당받아 서비스를 외부에 노출할 수 있습니다.

---

## 2. MetalLB의 주요 구성 요소

MetalLB는 크게 두 가지 컴포넌트로 실행됩니다.

* **Controller:** 할당할 IP 주소 풀(Address Pool)을 관리하고, 서비스가 생성될 때 적절한 IP를 할당하는 역할을 합니다.
* **Speaker:** 각 노드에서 실행되는 데몬셋(DaemonSet)으로, 할당된 IP가 현재 어떤 노드에 있는지 네트워크 프로토콜(ARP/BGP)을 통해 외부망에 알리는 역할을 합니다.

---

## 3. MetalLB의 두 가지 작동 모드

MetalLB는 네트워크 환경에 따라 두 가지 방식으로 동작합니다.

### ① 계층 2 모드 (Layer 2 Mode / ARP)

가장 간단하고 일반적인 방식입니다.

* **작동 방식:** 클러스터 내의 한 노드를 '리더'로 선정하고, 할당된 외부 IP에 대한 ARP 응답을 해당 노드가 대신 수행합니다. 외부에서는 마치 그 노드가 해당 IP를 가진 것처럼 인식합니다.
* **장점:** 특별한 네트워크 장비(라우터) 설정이 필요 없습니다.
* **단점:** 트래픽이 한 노드로 몰리는 병목 현상이 발생할 수 있으며, 장애 조치(Failover) 시 약간의 지연이 발생할 수 있습니다.

### ② BGP 모드 (Border Gateway Protocol Mode)

진정한 의미의 로드 밸런싱을 구현하는 방식입니다.

* **작동 방식:** 클러스터의 각 노드가 외부 라우터와 BGP 세션을 맺고, 트래픽을 분산시킵니다.
* **장점:** 여러 노드로 트래픽을 고르게 분산(ECMP 사용)할 수 있어 성능과 가용성이 뛰어납니다.
* **단점:** BGP를 지원하는 하이엔드 라우터가 필요하며 네트워크 설정이 복잡합니다.

---

## 4. 요약 및 특징

| 구분 | 내용 |
| --- | --- |
| **주요 목적** | 온프레미스 쿠버네티스에서 `type: LoadBalancer` 서비스 사용 |
| **주요 기능** | IP 주소 할당 관리 및 네트워크 광고(ARP/BGP) |
| **장점** | 클라우드와 동일한 사용자 경험 제공, 오픈소스 |
| **대안** | OpenELB, Kube-VIP 등 |

**MetalLB**는 별도의 하드웨어 로드 밸런서 장비 없이 소프트웨어만으로 클러스터 외부 노출 문제를 해결해주기 때문에, 사내 서버나 개인 실습용 라즈베리 파이 클러스터를 구축할 때 필수적으로 사용됩니다.
